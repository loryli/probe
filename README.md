# 个人 AI 面试助手

个人自用的 AI 面试练习工具，首发面向大模型应用开发 / AI 全栈。根据简历项目与个人题库动态提问，用带来源证据的记录复盘。

目前已实现 **后端基础骨架、个人题库、简历与项目、面试计划（Planner）与文字模拟面试的页面及 API**：题库 CRUD、内容历史、Markdown 预览导入，PDF 原件保存、文字提取与本地 OCR、简历版本、项目事实维护、Qwen 项目提取草稿与人工确认保存，固定资料版本的考察目标与预算规划，以及按已确认计划逐轮提问、保存回答、SSE 推送已保存的问题与整场复盘的文字面试闭环。页面直接操作后端保存的数据。逐轮后台分析与记忆尚未实现。项目设计见 [设计文档入口](docs/README.md)。

## 当前基础架构

- 一个 FastAPI 应用，使用应用工厂和 lifespan 管理资源。
- 前端采用独立的 Vue 3 + TypeScript + Vite 工程，包含题库、资料、计划与文字面试四个工作区。开发时由 Vite 单独端口运行并代理现有 API；生产构建由 FastAPI 同源托管，默认仍只启动一个服务。后端 API 与数据模型保持原有边界。
- Pydantic Settings 读取环境变量和 `.env`，敏感配置使用 SecretStr。
- SQLAlchemy 2.0 异步数据库会话；本地默认 SQLite，支持显式选择 MySQL，事务由业务服务管理。
- SSE 事件编码与流响应工具；文字面试在决策校验并落库后推送实际问题，事件本身不落库、不重放，不承诺模型首 token 逐字显示。
- 供应商无关的结构化输出协议，以及 Qwen Chat Completions 适配器（含流式）；请求限时、JSON 校验、调用用量与脱敏错误记录。
- UTC 应用日志、健康检查、离线测试、格式/静态检查和 GitHub Actions 配置。

## 本地启动

本轮流程调整增加迁移 `0011_optional_plan_resume`，让计划可不关联简历。local SQLite 仍在启动时应用已有迁移；显式 MySQL / 非 local 环境需先手工执行 `python -m alembic upgrade head`。迁移保留已有计划与场次，仅放宽简历关联，并要求 ID/版本成对为空或成对存在。SQLite 重建计划表使用独立迁移连接、暂时关闭该连接的外键并在提交前核对引用，普通业务连接保持外键启用。已有纯题库计划时禁止降级到强制简历结构，不自动删除记录。助手未执行迁移或验证。

需要 Python 3.11 或更新版本。以下命令适用于 PowerShell，从仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c constraints.txt -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn interview_assistant.main:create_app --factory --reload
```

macOS/Linux 使用 `.venv/bin/python` 替代 `.venv\Scripts\python.exe`。仅启动服务可安装 `-c constraints.txt -e .`，无需开发依赖。`pyproject.toml` 声明依赖范围，`constraints.txt` 记录当前验证过的版本；变更依赖时同步更新并重新验证。

新版前端位于 `frontend/`。开发需要 Node.js 20.19+ 或 22.12+：在一个终端启动 FastAPI，在另一个终端执行 `cd frontend; npm ci; npm run dev`，访问 <http://127.0.0.1:5173/>。Vite 将现有 API 路径代理到 `127.0.0.1:8000`。构建执行 `cd frontend; npm run build`，产物写入 `frontend/dist/`，之后 FastAPI 的 `/app/` 会托管完整构建版。开发服务器入口是 `/`；`/frontend-assets/` 是生产构建的静态资源前缀，不是开发页面入口。

默认本地模式无需填写数据库账号或创建数据库。首次启动会自动在 `data/interview.sqlite3` 创建独立的 SQLite 开发库，并通过 Alembic 准备表结构；题目和历史版本在重启后保留。`.env` 是可选配置，现有文件中的 `INTERVIEW_DATABASE_URL` 留空即可使用此模式。

默认监听本机 `127.0.0.1:8000`，访问：

- 题库：<http://127.0.0.1:8000/>，管理题目、分类、历史版本与 Markdown 来源。
- 简历与项目：<http://127.0.0.1:8000/materials>，维护简历版本、项目事实并核对 AI 候选。
- 面试计划：<http://127.0.0.1:8000/planner>，选择固定资料版本并生成、确认目标与预算。
- 文字模拟面试：<http://127.0.0.1:8000/interview>，按已确认计划练习并回看问答与复盘。
- Vue 应用入口：<http://127.0.0.1:8000/app/>。前端构建产物存在时提供四个新版工作区；未构建时返回明确的 503 启动提示；旧页面不再保留。构建后需重启后端以挂载资源。
- 前端选型、目录职责、统一视觉与运行方式见 [前端开发方案](docs/frontend/README.md)，业务保护规则见 [前端业务规则](docs/frontend/BUSINESS_RULES.md)。

四个页面的新建操作统一由页面右上角主按钮触发；空状态区域只保留引导文案，不重复放置按钮。
- Apifox 导入地址：<http://127.0.0.1:8000/openapi.json>，操作见下方「使用 Apifox 调试」。
- 进程存活：`GET /health/live`，成功返回 HTTP 200。
- 数据库就绪：`GET /health/ready`，本地数据库准备好后返回 HTTP 200；未配置或无法连接所选数据库时返回 HTTP 503。

不配置模型密钥也可使用题库。数据库就绪检查不代表 Qwen 已接入。

## 使用题库页面

清理题目时点击「批量管理」，可本页全选、移动所选或删除所选；翻页与更换筛选会清空选择，删除保留历史与来源。面试计划列表与详情均提供删除入口，失败记录也可移除；生成中的计划先读取完成或失败状态再删除，已有面试记录及冻结资料保留。

**只练题库**：进入「面试计划」，选择「纯题库练习」 → 勾选题目 → 设置方向和时长 → 生成并确认计划 → 开始练习。无需上传或创建简历、项目；计划由规则整理，不调用规划模型。场次可选择 AI 反馈或规则练习，题目一律取冻结版本的题库原题，不由 AI 改写、补题或额外追问。若一个目标包含多题，不因单次回答达标而跳过同组剩余原题；时长仍为参考，用户可主动结束或跳过目标。

**项目面试**：上传 PDF → 核对提取文字 → 点击「保存并 AI 填写项目」→ 自动打开填好的第一个项目表单。主字段为项目名称、技术栈、简介、多条描述；每条描述只有一个主要编辑框，原文依据按需展开。逐个核对保存后可接着填写下一项目，再以固定版本生成面试计划。新建简历模拟面试先进行自我介绍和项目介绍，之后才结合本场介绍、冻结资料和目标动态提问；纯题库直接进入原题。已有场次保留原进度，不强行补开场。也支持仅保存简历、稍后点击 AI 填写，以及本地规则备选或手工添加。不会因上传、刷新或模型完成就自动保存正式项目。

项目描述沿用已有事实存储与来源校验；本轮没有改写用户原题、答案或已有项目。新计划额外冻结项目简介和周期用于上下文，旧计划缺失这些字段时保留空值，不借用今天的资料补造历史。提取提示升级为 `resume_extract.v3`，避免把项目标题、日期、空标签或整页正文重复填成一条描述；历史提取结果仍可查看，也可明确重新 AI 填写。

- 点击「新建题目」，填写题干、自己的标准答案和复习笔记后保存；答案与笔记可留空。
- 左侧按题干搜索、按启用状态筛选并分页；选中一道题即可编辑。支持 `Ctrl+Enter` / `⌘+Enter` 保存。
- 「用于面试抽题」开关控制启用状态，点击保存后生效；面试计划会把启用题目作为候选池。
- 「历史版本」查看历次内容原文，切换版本不会覆盖当前编辑内容。删除题目需确认，后端保留历史记录。
- 列表勾选后可批量移动分类或批量删除题目（逻辑删除，保留历史与来源引用）；分类管理弹窗可逐个删除空分类，也可用「清理空分类」一次删除全部空分类。分类只有在没有未删除题目时才可删除，题目与已确认计划不受影响。
- 未保存的内容在切换题目、新建或离开页面时提醒确认；请求失败时保留输入，创建请求重试使用幂等标识。
- 若 Apifox 或其他页面修改了同一道题，保存时会提示版本冲突并保留草稿，可先复制输入再「读取最新内容」。

文本框显示和编辑 Markdown 原文；阅读区的答案与笔记按有限的 Markdown 子集渲染（标题、段落、列表、代码围栏、引用、分隔线，行内加粗/斜体/删除线/行内代码/`http(s)` 链接），由 Vue 组件生成节点，不使用 `innerHTML`，不解析 HTML、不加载图片、不执行其中的指令。仅发送实际改动的字段，避免编辑笔记时改写未触碰的答案换行。页面不内置演示题目，不使用浏览器本地存储代替数据库。

## 导入 Markdown 笔记

1. 在首页点击「导入 Markdown」，选择 `.md` / `.markdown` 文件。首版支持 UTF-8（含 BOM），单个文件最多 1 MiB、500 个候选段落；其他编码先在编辑器中另存为 UTF-8。
2. 点击「生成预览」。自动识别优先使用三级标题；没有三级标题时，优先识别 Q/A 标记，否则使用二级标题。也可手动选择三级标题、二级标题或 Q/A 模式。
3. 核对候选题干、答案、来源行号与提示；可按建议勾选、全选、全不选或逐题选择。题干为空不能导入；缺少答案不会自动补写。说明性段落、空答案和文件内完全重复的条目默认不选中，可人工核对后选择。
4. 点击「确认导入」，选中题目、第一份内容版本和来源引用在一个事务中保存；任一写入失败均回滚。预览阶段只保存导入草稿，不创建题目，关闭预览也不会确认入库。
5. 在题库选中导入题目，通过「来源原文」查看对应段落或下载完整来源文件。之后编辑题目不改变导入时的来源记录。

识别规则：标题作为题干，保留编号与 Markdown 转义；标题下存在「面试题：」等明确标记时提取该题干。答案保留标准回答标记、代码块、补充说明、Markdown 图片标记及原有换行；标题标记之后的排版空行不计入答案正文（解析器版本 `markdown-v2`，旧批次仍按导入时版本显示）。代码围栏和缩进代码中的标题、Q/A 标记不作为拆分点；同级或上级标题结束当前段落。前言、分类标题等未入题库的内容仍在完整来源文件中。图片只保留标记，不读取图片、执行 HTML 或调用模型。规则是确定性的文本提取，不是通用 Markdown 语义解析；自动结果不合适时先切换识别方式核对。

导入草稿、源文件全文、SHA-256、解析器版本与来源行号存入所选数据库，不在源码目录另存上传文件。同一内容、同一识别方式与同一解析器版本复用草稿，或复用导入题仍存在的已确认批次，文件改名仍沿用首次记录的文件名。每个批次只确认一次，请确认前核对选择；同样选择可安全重试，改选后重复确认返回 HTTP 409。已删除的导入题不会因重试旧批次而恢复；删除后可重新上传同一文档，此时创建新批次并重新选择导入，旧批次、来源与删除历史保留。文件或识别方式变化形成新批次，不做跨批次或语义去重。

网络异常导致确认结果未知时，页面保留并锁定本次选择，可点击「重试确认」；重新打开页面后也可选择原文件、使用相同识别方式重新预览，以读取批次状态。

## 简历与项目管理

已有环境需先安装新增的 PDF 依赖，然后按原方式启动或重启服务：

```powershell
.\.venv\Scripts\python.exe -m pip install -c constraints.txt -e .
.\.venv\Scripts\python.exe -m uvicorn interview_assistant.main:create_app --factory --reload
```

本轮未执行依赖安装、数据库迁移、模型下载或任何测试/浏览器验证。PDF/OCR 依赖已记录在依赖文件，但未在本地验证。local SQLite 会在启动服务时自动升级到当前迁移头（见「配置与数据库」）；显式 MySQL 仍需手工运行 Alembic 迁移。

1. 在前端点击「简历」。已有简历从左侧选择；添加新简历使用「上传简历 PDF」或「上传新简历」，次要入口支持粘贴文字。
2. 上传 PDF，核对提取文字，填写名称后保存。PDF 最多 10 MiB、50 页；提取文字最多 1 MiB。没有 PDF 时可通过次要入口直接粘贴简历文字。
3. 默认「自动」模式先提取文字，对有效文字不足 20 个字母/数字/汉字的页面进行本地 OCR；混合 PDF 按页处理，不重复拼接原有页眉。可选「整份 PDF 使用 OCR」处理提取错乱或文字较多但仍有扫描内容的文件，或选「仅提取已有文字」关闭 OCR。加密 PDF 仍需先导出未加密副本。OCR 可能出现错字、数字或顺序错误，请人工核对。[文字提取限制见 pypdf 官方说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)。
4. 上传 PDF 时先保存原件和提取结果，点击「保存简历」才创建简历或新版本。相同 PDF 字节复用同一份原件，并沿用首次文件名；关闭页面不删除上传原件。相同字节 + 相同识别方式会复用已有识别结果（页面明确提示，响应 `cache_hit=true`）。已有 PDF 可更改识别方式后点击「重新提取」——该操作跳过缓存真正重跑识别并覆盖缓存，核对结果后再保存；未保存前不会更新简历，也不改变已有项目依据。原始字节不被 OCR 或人工修正改写。
5. 保存简历后，在「简历中的项目」明确点击 AI 填写项目，核对后保存；也可手工添加项目，维护名称、职责、时间、技术栈、说明和事实。每条事实可记录类型、内容与可选原文引用；引用必须匹配该项目所绑定简历版本中的连续文字。匹配时忽略空白排版差异（换行转换、多余空格、全角空格、不间断空格等），措辞仍须逐字同源，入库保留来源中的实际原文（含原始换行）。无引用的条目明确标为「手工补充」。新建或编辑项目时可展开「从简历原文选取事实」，勾选当前绑定版本的段落，原文会同时填入事实内容与引用；这是确定性文本选取，不调用模型。简历没有可选取内容或未发现明显项目段落时会提示，仍可手动逐条添加。
6. 可勾选「我已核对」；继续编辑项目会取消该勾选，保存前可重新确认。现在可使用下方 Qwen 提取草稿流程辅助整理，仍需人工核对。OCR 只用于 PDF 文字识别，Markdown 题库中的图片仍不识别。
7. 简历名称、文字或来源变化时原子保存新版本；启停只更新修改版本。历史页可读取旧文字及对应 PDF。项目固定绑定创建时的简历版本，更新简历不会悄悄重绑来源；如需基于新版重新整理，可创建新项目。

OCR 输出根据文本框坐标合并同一视觉行，按标题、条目和长句整理分段，不再把每个文本框直接作为独立段落。对「姓／名：」等有冒号佐证的已知字段修复断行，不修改词句、数字或推测缺失内容。已载入或粘贴的文字也可点击「整理换行」，结果只进入当前草稿，可立即「撤销整理」；手工继续编辑或保存后清除该次撤销入口。复杂多栏、旋转文字和识别杂字符仍需人工核对。

本次升级了提取结果缓存版本，旧 PDF 点击「重新识别当前 PDF」会使用新的排版规则，不复用旧格式结果；已保存的简历与项目依据不会自动修改。未运行识别或页面验证。

简历、项目支持逻辑删除和并发修改保护。删除简历后关联项目从普通接口与页面隐藏，版本、PDF 和项目事实保留；编辑事实时旧事实记录保留，不覆盖来源文字。本阶段提供简历历史页面，不提供项目编辑历史页面。未保存输入在切换资料或离开页面时提醒，失败时保留输入。创建重试沿用同一个 UUID `Idempotency-Key`。

OCR 使用 [RapidOCR 与 ONNX Runtime](https://rapidai.github.io/RapidOCRDocs/main/quickstart/) 在本机执行，由 [pypdfium2](https://pypdfium2.readthedocs.io/en/stable/python_api.html) 将 PDF 页面渲染为图像。首次实际识别会下载检测、方向分类和识别模型，后续复用本地文件；简历文字与页面图像不上传。默认模型目录为所配置 `data/` 下的 `ocr-models/`，可通过 `INTERVIEW_OCR_MODEL_DIR` 指定可写目录。模型无法下载时页面给出提示，可联网重试、预先准备模型目录或手工补充文字。应用启动本身不加载 OCR、不下载模型。

识别结果按 PDF 原件、识别方式和提取版本缓存，记录 OCR 页码、逐页处理方式与核对提示；已有简历版本不会被重新识别覆盖。上传相同字节的 PDF 会复用已有的同方式结果（响应里 `cache_hit=true`，页面提示「已复用已有识别结果」）；页面上的「重新提取」始终真正重跑一次识别并用新结果覆盖该缓存，不再静默返回旧结果。自动模式遇到 OCR 错误时返回可用的提取文字及提示，且不缓存失败结果；整份 OCR 模式失败则返回错误并保留当前编辑输入。当前提取版本 `pdf-v5`：300 DPI 渲染 + medium 检测模型 + small 识别模型，且整页不再被引擎压缩（输入上限 4200px，与渲染上限一致）；扫描页单页识别约 45–55 秒（此前约 9 秒），首次识别多页扫描件时请耐心等待，页面单次等待上限 10 分钟；超时可稍后重试（服务端会继续完成并缓存）。PDFium 渲染和 OCR 引擎调用在进程内串行处理，识别期间不持有数据库事务。

资料接口统一在 `/materials` 下：

| 路径 | 行为 |
|---|---|
| `POST /materials/documents/pdf?file_name=...&ocr_mode=auto` | binary PDF 上传，保存原件并返回文字、OCR 页码和提示；识别方式支持 `auto/force/off`；相同字节与方式命中缓存时返回 `cache_hit=true`。 |
| `POST /materials/documents/{id}/extract?ocr_mode=force` | 使用已保存原件重新识别：跳过缓存真跑一次，用新结果覆盖同键缓存，返回预览，不修改简历。 |
| `POST /materials/text/format` | JSON 提交 `source_text`，返回只整理断行和空白的文本，不写数据库、不调用模型。 |
| `GET /materials/documents/{id}/file` | 下载原始 PDF。 |
| `GET/POST /materials/resumes` | 按名称搜索、分页列出或创建简历。 |
| `GET/PUT/DELETE /materials/resumes/{id}` | 读取、保存完整内容或逻辑删除。 |
| `GET /materials/resumes/{id}/versions` | 分页列出简历版本。 |
| `GET /materials/resumes/{id}/versions/{version}` | 读取指定版本文字、来源文件和哈希。 |
| `GET/POST /materials/resumes/{id}/projects` | 分页列出或创建项目及事实。 |
| `GET/PUT/DELETE /materials/resumes/{id}/projects/{project_id}` | 读取、保存项目与事实完整内容或逻辑删除。 |

资料的 `PUT` 接口提交完整可编辑内容和 `expected_revision`；项目来源版本创建后不可改写，事实随项目在同一事务中保存。`POST` 创建可带 UUID `Idempotency-Key`，同一标识与内容重复请求返回已有记录（HTTP 200）；不同内容或已删除记录返回 409。删除通过查询参数提交 `expected_revision`。详细结构以 OpenAPI 为准。

## Qwen 提取项目与事实

在本地 `.env` 配置（密钥不发到聊天中，也不要提交仓库）：

```dotenv
INTERVIEW_QWEN_API_KEY=你的百炼APIKey
INTERVIEW_QWEN_MODEL=qwen-plus
INTERVIEW_QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
INTERVIEW_QWEN_ENABLE_THINKING=false
INTERVIEW_QWEN_TIMEOUT_SECONDS=120
INTERVIEW_QWEN_RESUME_TIMEOUT_SECONDS=240
INTERVIEW_QWEN_MAX_OUTPUT_TOKENS=8192
INTERVIEW_QWEN_INTERVIEW_TEMPERATURE=0.8
# 默认忽略系统/环境代理直连 DashScope；本地代理会把流式首字从亚秒拖到数秒。
INTERVIEW_QWEN_TRUST_ENV=false
```

`qwen-plus` 是可替换的配置示例，不锁定最终型号。接口使用 Chat Completions 的 JSON Object 模式，并由 Pydantic 校验实际结构；所选模型需支持对应 JSON/思考模式组合。默认接口地址是北京地域现有域名，也可改为百炼控制台的业务空间专属地址；密钥和接口需同地域。[百炼兼容接口说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

重启后进入「简历与项目 → 项目与事实」：

1. 先保存并核对简历文字，再点击「AI 提取项目」。仅此操作发送已保存版本文字到所配置的 Qwen 接口，不上传原始 PDF；最多处理 60000 字符，超出时提示精简，不静默截断。
2. 提取结果保存为待确认草稿，显示候选项目、事实原文引用和需确认事项。新版模型只标注连续原文行号，由服务端还原事实正文与引用，非法范围被排除并提示；历史草稿继续兼容原文引用校验。引用存在不等于项目归属或事实真实性已核实，模型置信度也不代表真实性。没有候选时说明限制，并提供本地规则备选与手工选取原文，不把空结果包装成成功。
3. 对候选点击「载入编辑」，在已有项目编辑区修正名称、职责、时间、技术栈、说明与事实。未知字段留空，不根据技术名词自动补写实现细节，也不替用户修复简历缺失句子。
4. 勾选「我已核对」后点击「确认并保存项目」。每个候选独立确认，在一个事务中保存项目、事实与确认映射；重复提交相同内容读取已保存项目，不重复创建。已保存候选需从项目列表修改，删除后不会因重试重新创建。
5. 提取草稿持久化，可刷新结果、切换历史提取记录及分页查看；刷新/读取记录不调用模型。新提取记录不会覆盖原简历或已有项目，不同提取任务之间不做语义去重。
6. 提交后接口立即返回 `running` 草稿，模型在服务端后台任务里用独立数据库会话执行，不占用 HTTP 请求。页面每 2 秒读取一次草稿状态（唯一轮询源），显示已用时间但**不显示进度百分比**——模型耗时不可预估；可点「停止等待（后台继续）」离开或稍后点「读取本次结果」，任务不会因页面关闭而中断，也不会重复发起模型调用。运行中不显示「没有项目事实」的空状态。

超时或网络错误时页面保留请求标识，按钮变为「读取本次结果」，点击复用该标识读取原任务，不发起第二次调用。已明确失败的提取不会自动重试，再次点击「AI 提取草稿」才创建新任务和新模型调用。因重启等原因遗留的运行中任务在超时宽限期后标为失败，不自动续跑。已有草稿和人工项目管理不依赖模型密钥。

每次任务记录模型、prompt/schema 版本、状态、耗时、服务端返回的输入/输出 token 用量及脱敏错误码；不存储无效模型原始响应，不记录密钥、请求正文或简历到日志。提取和确认均固定引用具体简历版本，后续修改简历不重绑依据。运行期间的 JSON 与来源校验属于业务逻辑；本轮未运行测试、浏览器验证，也未实际调用 Qwen。

### 提取超时与备用路径（2026-11-12）

- 读取本地已有任务记录发现：最近 5 次调用均约 120 秒超时，同一份简历为 3128 字符；没有进入结果结构或来源引用校验。旧非流式调用无法区分网络等待和模型生成慢，不能凭此断言供应商或网络故障。
- 新提取提示版本 `resume_extract.v2` 使用编号原文行，模型只返回项目字段和事实行号；内部模型契约是 `resume_extract_refs.v1`。事实内容与证据由后端从该版本原文连续截取，不再让模型重复抄写。无效行号被排除并提示。保存草稿仍为 `resume_parse.v1`，历史草稿和确认流程兼容。
- 模型响应改为流式接收，完成结构校验前不写入可确认结果；`[DONE]` 后结束接收。超时提示区分连接超时、尚未收到正文、收到部分正文但未完成；日志记录首段耗时和总耗时，不含资料或响应正文。
- 简历提取单独使用 `INTERVIEW_QWEN_RESUME_TIMEOUT_SECONDS`，默认 240 秒，上限 300 秒；提取显式关闭思考，实时面试仍使用原来的时限。修改本地配置后重启后端。
- 页面新增「本地规则备选」，失败区也提供入口。它按「项目经历」章节、日期/标题（包括日期与项目名同一行）、Markdown 标题或显式项目名称分组，事实逐字取原文，不调用模型，不推断角色/技术栈/成果；无法可靠识别时提示手工添加和选取原文。规则结果单独保存为 `provider=local_rules` 的候选，沿用逐候选人工确认，不覆盖 AI 失败记录或项目。
- 提取提交增加可选 `mode=model|rule`（默认 model），草稿读取增加 `provider`。rule 直接返回本地候选，不排后台模型任务；无需配置密钥。重复读取/提交同一标识不重复创建草稿或项目。Apifox 从 `/openapi.json` 更新导入，无需迁移或重装依赖。
- 验收路径：重启后进入资料页，使用「本地规则备选」→逐项核对保存→携带当前版本创建计划；需要时再明确点击 AI 提取。原任务仍在后台时改用本地规则，只停止页面等待，不自动发起其他收费调用。
- 本轮只读取已有任务元数据及项目标题结构，没有修改用户数据库、运行测试/构建或调用模型。真实 Qwen 恢复情况和规则候选边界均待用户启动验收。

原文质量提示：引用能匹配不代表原文完整。候选读取时检查未配对的中文引号/括号、替换字符与异常控制字符，在项目和事实编辑区显示待核对提示；这是排版疑点，不能自动断言 OCR 错误或推断缺字。历史草稿仅派生提示，不改原文、历史结果、revision 或模型自评分。用户可移除残缺的草稿事实并保留其他完整事实，或对照 PDF 手工修正简历、保存新版本后重新提取；旧项目和已确认计划不自动换绑。

新增接口（更新 Apifox 的 `/openapi.json` 导入）：

| 路径 | 行为 |
|---|---|
| `GET /ai/status` | 只读取本地配置状态与模型名，不发网络请求，不返回密钥。 |
| `POST /materials/resumes/{id}/parse-drafts` | 提交 `request_id` UUID、`source_version` 与可选 `mode`。默认 model 立即返回 `running` 草稿，由独立后台会话调用模型；rule 不调用模型，直接返回本地待核对候选。相同标识重放只读取原任务。用 `GET /{draft_id}` 轮询终态；失败体现在 `status/error_code/error_message`，不创建项目。 |
| `GET /materials/resumes/{id}/parse-drafts` | 分页读取提取历史，`limit` 最多 20。 |
| `GET /materials/resumes/{id}/parse-drafts/{draft_id}` | 读取任务结果、revision 和已确认候选映射。 |
| `POST /materials/resumes/{id}/parse-drafts/{draft_id}/confirm` | 提交候选序号、`expected_revision`、完整可编辑项目字段和 `user_verified=true`，确认一个项目。 |

首次使用只需按原命令重启服务，local SQLite 自动升级到当前迁移头（见「配置与数据库」）；显式 MySQL 需手动 `alembic upgrade head`。网络调用复用现有 `httpx2` 包，已将其声明移到运行依赖，不引入供应商 SDK。

## 面试准备与 Planner

打开 <http://127.0.0.1:8000/planner> 或点击侧栏「面试计划」。先选择练习模式，再准备范围、生成并确认计划，随后可进入文字模拟面试。

1. 选择简历与具体简历版本，勾选该版本中已核对的项目（最多 8 个）和启用题库中的题目（最多 40 道）。启用题库**默认从全部启用题目中随机抽样 40 道**（不再只取最近 200 道），可点「随机重选 40 道」重新抽取或逐题调整。题目列表按导入批次时间与候选序号还原笔记原顺序；随机只决定「选哪些」，提交时按页面列表顺序固化，不改变题目先后。未核对、版本不匹配、已停用或已删除的资料会被排除并给出提示。
2. 填写考察方向（可留空）、预计时长（10–180 分钟）、项目题时间比例与追问设置。追问设置分为自动分配、禁止额外追问和指定上限；API 的 `max_total_followups=null` 表示自动、`0` 明确禁止、正整数指定全场上限。已确认计划仍使用原冻结结果，不重新计算额度。目标时长只是节奏参考，到时不强制结束。
3. 选择生成方式后点击「生成计划」。模型模式复用上一节的 Qwen 配置与 `ai/qwen.py` 适配器，仅发送已核对项目事实与启用题干，不发送简历全文、标准答案或复习笔记；规则模式完全在本地按资料分块生成，不调用模型，适合核对流程或密钥未就绪时使用。两种模式都会先确定「哪些来源参与、每类分几个目标」，再分配预算；比例为 0 的来源不会留下零预算目标。
4. 计划输出考察目标（主题、来源、优先级、可观察证据、完成规则、事实与题目引用）、题源时间预算、开场与收尾缓冲、追问总上限与每目标上限，以及分区提示。**不输出固定问题清单，也不生成任何具体问题文本**。摘要、比例换算、时间分配、追问配额、目标编号、覆盖率、候选范围与引用校验全部由服务端程序生成，模型只返回语义骨架。
5. 结果区按来源分区显示「系统校验与统计」「模型提示 · 未经核验」「产品规则」；含与所选简历版本不符的版本号的模型提示会被剔除。每个目标可展开核对引用的事实原文与启用题干，并查看预编译的运行时上下文；覆盖率卡片显示目标依据的覆盖比例，候选范围卡片显示本场可以动态选用的资料池。
6. 可查看历史计划、调整输入后重新生成（每次生成是一条新记录，不覆盖旧计划）、确认保存或逻辑删除。**确认前复核固定引用**：简历版本哈希、项目 `revision`、事实内容/类型/来源依据与题目内容版本任一变化，或资料被停用、取消核对、删除，都会返回 409 并要求重新生成。
7. 页面会区分「配置已改」与「计划可确认」：调整时长、比例、资料或题目后，旧结果的确认按钮会被禁用并提示重新生成；生成期间输入被锁定，避免结果与界面配置不一致。「读取本次结果」只读取原任务，未结束时保留入口，不重复调用模型，也不自动重试收费请求。

### 规划质量与实时链路约束

Planner 决定后续提问水平，也影响语音对答的反应速度，因此按以下原则收敛：

- **模型职责最小化**：发给模型的只有项目事实摘要（每条至多 120 字）与启用题干（每道至多 80 字），不含简历全文、标准答案或笔记；模型只输出主题、来源、优先级、引用 ID、最多 3 条能力维度与简短完成规则，不输出摘要、时间、预算或具体技术细节，也不复述技术路径、指标与版本号。
- **原文保真与消费层分离**：Markdown 导入规则、来源全文与题库内容版本一律不改；`planner/text.py` 只在组装模型输入与 `runtime_context` 时做逐行保序清理（转义反斜杠、强调标记、行首编号、`【标准回答话术】` 类标签、多余空行），不重排行、不删非空行、不合并段落，也不写回题库。项目事实保留逐字原文以维持证据可核验；计划快照按提交顺序输出题目，不再按创建时间重排。
- **格式容错、语义严格**：空白、长度、数量与未知字段在校验前自动裁剪，避免一条多余证据让整份计划失败；但 `schema_version`、来源枚举、优先级、引用 ID 与资料范围严格校验，不合法直接失败并给出可操作提示，不把非法输出包装成合法结果。
- **候选范围与目标依据分开**：计划保存 `candidate_scope`（本场允许动态选用的全部事实与题目），目标的 `project_fact_ids` / `question_ids` 只是该目标的主要依据。覆盖率表示目标引用情况，不承诺整场问完，也不为凑覆盖率强行加题。
- **提示分层**：模型自评一律标注「未经核验」，不与系统校验结果、产品规则混排；含未核验版本号的条目直接剔除，目标数按预计时长程序化确定（4–8 个）。
- **追问配额公平分配**：先给每个有意愿的目标保底 1 次，再按优先级分配剩余额度，避免尾部目标全部为 0 追问。
- **结构化运行时契约**：`GET /interview-plans/{id}/runtime` 返回 `interview_runtime.v1`：目标的结构化引用 ID、可观察证据、完成规则、预算、候选范围，以及确认时冻结的完整资料快照（含题干、标准答案与备注原文）。`context` 字段只是摘要，用于选择方向；提问、保存来源与复盘必须按 ID 读取快照原文，不能从截短文本恢复原题。
- **旧计划只读**：优化前生成的计划（`planner.v1`、快照缺 `revision` / 来源依据）仍可在列表与详情中查看，但确认与运行时接口返回 `plan_contract_outdated` 409，必须按当前配置重新生成；页面同时禁用其确认按钮。当前提示词版本为 `planner_prompt.v4` / `planner_rule.v3`。

计划固定引用所选简历版本，并保存生成时的项目 `revision`、事实内容与来源依据（`source_kind` / `evidence_quote`）、题目内容版本与标准答案原文，作为确认复核与运行时读取的冻结依据。local SQLite 重启后自动升级到当前迁移头；显式 MySQL 需手动 `alembic upgrade head`。本轮无新迁移、无新依赖，也未运行迁移、测试、静态检查、浏览器验证或模型试调用。

## 文字模拟面试

打开 <http://127.0.0.1:8000/interview> 或点击侧栏「模拟面试」。本轮交付最小闭环：已确认计划 → 创建场次 → 首问 → 提交回答 → 追问或切题 → 结束，问答逐轮保存，刷新后可继续或回看。

1. 选择一份**已确认的计划**开始。只有满足当前契约（`planner.v2` 结果、`snapshot_version=2` 快照、项目 revision 与题目原文齐全）的计划才能开始；旧版计划仍会列出来但置灰，页面直接提示去「面试计划」页按当前配置重新生成并确认，不会等到点「开始」才报 409。创建场次时把 `interview_runtime.v1`（目标、预算、约束、候选范围与冻结资料快照）复制进场次；之后修改计划或资料不影响进行中的场次与历史记录，绕过页面直接调用时旧契约仍返回 `plan_contract_outdated`。
2. 创建场次时**只为第一个待考察目标预生成基础问题骨架**并写入 `outline_json`（`interview_outline.v1`，每个项目目标最多 2 题，只依据该目标的项目事实）；其余目标在真正轮到它时按目标增量补齐（同样的 2 题小调用）。预生成的目标顺序与出题顺序一致（同为场次打乱后的第一个目标），所以开场只有一次模型调用；模型漏掉该目标时用规则骨架补位，**骨架必命中**，不会再回落到即时生成。骨架生成失败、密钥未配置或旧场次没有骨架时仍可回退到即时生成，不阻断开始；首问最终没生成出来时接口不返回 500，而是把场次连同 `error_code` 返回，页面提示可点「继续生成下一问」重试。题库目标不进骨架，仍直接使用**你自己的原题**（完整题干按冻结版本展示）。发送给模型的只有该目标的事实摘要与题库题干，不含简历全文、标准答案或笔记。
3. 提交回答后先保存并提交事务，再调用模型。`POST /interviews/{id}/answers/stream` 先回 `ack`；模型内部仍流式接收，但完整校验、来源与额度守卫、并发检查以及下一问落库后，才将实际问题以 `delta` 推送，最后发送 `state`。等待期间显示生成状态，不提前展示可能被拒绝的模型措辞；不承诺首 token 即逐字展示。
4. 追问同时受全场、单目标额度与有效时间预算约束。被拒绝的追问不能改名为普通续问；同目标基础题使用已保存骨架或事实模板，题库基础题必须读取冻结原题并推进游标。项目目标最多 2 个基础问题；模型可建议提前切换目标。题源切换优先补足相对预算消耗较少的来源，同题源按优先级和场次顺序选择。目标超出参考预算时可先让位，剩余基础题保留，其他目标结束后可继续；不会按时间清空目标或强制结束。
5. 计划时长只是节奏参考：到时不强制结束，也不中断正在作答的一轮；超出目标 60 秒后不再新增追问，混合面试中用满单目标预算且还有其他未完成目标时，下一问会让位给其他目标（按题源预算份额挑选），被让位目标保持待考察、剩余基础题稍后回来问完，不因到时丢题或强制结束。场次由用户主动「结束练习」，或在所有考察目标完成后自动结束。
6. 支持暂停 / 继续 / 跳过当前目标 / 结束。暂停起点、累计暂停秒数、目标有效耗时写入现有进度 JSON；暂停不消耗场次或目标预算，刷新、恢复和复盘采用同一时钟。写回模型结果前重新加锁核对状态与轮次，过期结果丢弃。旧场次此前未记录的暂停时间无法反推，不改写历史报告。
7. 模型失败（超时、无效 JSON、未配置密钥）保留已保存回答与待决策标记；手动重试只重跑此步，不重复保存，也不自动重试收费请求。未通过校验的问题不发送到页面。创建场次和提交回答仍受幂等键与唯一约束保护。
8. 规则模式完全本地运行：项目题按事实模板生成，追问按回答长度判断，用于无密钥核对闭环。规则模式不做语义判断，提问质量明显低于模型模式；它没有流式增量，一次把整句推给页面。
9. 同一份计划重复练习时每场问题不同：目标顺序（同优先级内）、题库取题顺序、项目事实顺序都由**场次 ID 派生**的顺序决定，同场次内稳定可复现，不同场次不同；题库题还会按同计划历史场次的出现次数排序，没问过的排前面。模型模式的判定与出题温度由 `INTERVIEW_QWEN_INTERVIEW_TEMPERATURE`（默认 0.8）控制，并把本场已问题目与同计划历史场次的近期问题一起发过去，明确要求换角度、不重复。考察目标本身不随机——每场覆盖的目标集合与完成标准仍来自冻结计划。
10. 首字延迟与整段延迟分开看：流式路径下第一个字通常在 1 秒左右到达，整句 1.5–3 秒说完（qwen-plus 实测：首帧 0.5s、`say` 从 0.8s 起逐字流出、单轮全程约 2s）。**Qwen 客户端默认忽略系统代理**（`INTERVIEW_QWEN_TRUST_ENV=false`）：本地代理软件会把 DashScope 延迟放大 5 倍左右，流式效果直接退化成"等几秒后整句蹦出"，这是本机部署最常见的假故障。确需走代理时显式设 `INTERVIEW_QWEN_TRUST_ENV=true`。输入也做过裁剪（每个目标最多 5 条事实、每条 280 字，最近 3 轮对话，已问/历史问题各 4 条），因为预填长度直接计入首字延迟；流式调用的 token 用量经 `stream_options` 随最后一帧返回并落库。
11. **整场复盘（Offline Path）已落地**：场次结束后在页面点「生成复盘报告」，一次模型调用（同步等待约 15–40 秒）产出 `interview_report.v1`——整体达成度（solid/mixed/weak）、120 字摘要、逐目标评价（covered/partial/missed、亮点与缺口、证据轮次引用）、弱项主题、下次练习建议与矛盾/待核验线索。每场一份：重放同一 `request_id` 或已有成品都直接返回，不重复调用；失败落库为可重试状态，不影响问答记录。规则模式或未配置密钥时降级为统计报告（覆盖数、每目标问答索引），提示用模型模式获取语义评价。题库目标的标准答案**只在复盘阶段**作为对照参考发给模型；实时面试仍不发送。

「回答先保存再调用模型、请求防重复、写回前检查场次状态」这三条是本轮的设计前提，后续加 SSE、断线重连与后台分析时不应绕过。

新增接口（更新 Apifox 的 `/openapi.json` 导入）：

| 路径 | 行为 |
|---|---|
| `GET /interviews/options` | 只读返回已确认计划与模型配置状态，不调用模型；每份计划带 `usable` 与不可用原因 `reason`，服务端已按当前契约判定，可用计划排在前面。 |
| `POST /interviews` | 提交 `request_id`、`plan_id` 与 `mode`，创建场次并生成首问；相同标识与配置重放原场次（HTTP 200），不重复调用模型。首问生成失败时仍返回 201 与场次快照，错误写在 `error_code`（如 `next_question_failed`），由 `POST /retry` 补。 |
| `GET /interviews` | 分页读取场次摘要（状态、轮数、目标进度），不加载完整资料快照。 |
| `POST /interviews/batch-delete` | 提交 `session_ids`（最多 50 个）批量删除记录：连同全部问答轮次与整场复盘物理删除，不可恢复；包含进行中的场次返回 409 且整体不删除。已确认计划不受影响。练习页「记录管理」使用该接口。 |
| `GET /interviews/{id}` | 读取场次、目标进度、全部轮次与当前问题。 |
| `POST /interviews/{id}/answers/stream` | **页面使用的路径**：提交 `request_id`、`turn_id` 与 `answer_text`；先落库，再以 `text/event-stream` 依次推 `ack`（已保存的快照）、`delta`（`{"text": "..."}`，面试官的话逐段到达）、`state`（完整场次）或 `error`。 |
| `POST /interviews/{id}/answers` | 同一动作的非流式版本：回答落库并提交后立即返回，决策在后台执行，结果由 `GET /events` 推送。保留给不支持流式读取的调用方。 |
| `GET /interviews/{id}/events` | 订阅场次进度（SSE）：快照变化时推送 `state`，生成完成、可作答、场次结束或出错后关闭；空闲 15 秒发心跳，最长 180 秒。刷新页面后用它与后台任务重新汇合。 |
| `POST /interviews/{id}/retry` | 续接未完成的一步：补首问或重跑失败的决策，不重复保存回答（同步等待，用于后台任务丢失后的恢复）。 |
| `POST /interviews/{id}/pause`、`POST /interviews/{id}/resume` | 提交 `expected_revision`，暂停或继续。 |
| `POST /interviews/{id}/skip` | 提交 `expected_revision`，跳过当前目标并生成下一问。 |
| `POST /interviews/{id}/end` | 提交 `expected_revision`，结束场次并保留全部问答与目标进度。 |
| `POST /interviews/{id}/report` | 为**已结束**的场次同步生成整场复盘（约 15–40 秒）；每场一份，重放同一 `request_id` 或已有成品直接返回（HTTP 200），新生成返回 201。失败返回报告的 `status=failed` 与错误信息，可用新 `request_id` 重试。 |
| `GET /interviews/{id}/report` | 读取已生成的复盘；未生成过返回 404（`report_not_found`），进行中场次同样 404，生成用 POST。 |

已知边界：逐字流式是**单进程内存通道**实现的——后台决策把增量写进进程内的 `LiveStream`，`answers/stream` 从它读出并转发。实时通道（内存状态、后台任务、SSE 帧与事件轮询）已集中在 `interview/streaming.py` 的 `StreamBroker`，多 worker 部署时替换该实现即可，路由与服务层无需改动；断线重放中间文字仍需事件持久化。断开连接不会取消后台任务，重进页面能拿到落库结果，但**已经流过的中间文字不会重放**（`GET /events` 只推完整快照）。`GET /events` 仍是轮询数据库的降级实现（每 0.35 秒比对一次），用于刷新后汇合，不是事件总线。后台任务随进程存活，服务重启会让进行中的一轮停在「重试下一步」，需手动续接。模型失败时已流出的文字保留，页面按 `error` 帧提示。复盘为同步生成（一次调用约 15–40 秒），暂无流式与后台队列；模型失败保留 failed 状态可重试，不丢整场记录。本轮不提供逐轮后台分析与记忆候选；删除场次已在练习页「记录管理」中提供批量入口，可勾选最近记录批量删除，物理移除场次、全部轮次与整场复盘，进行中的场次需先结束或暂停，已确认计划不受影响。暂停时长计入已用时间。暂停或结束会丢弃迟到的决策结果，恢复后需要点「重试下一步」。面试侧的标准答案仅保留在快照与会话中，实时提问不发送给模型；复盘阶段会作为对照参考随题库目标一起发送。升级前生成的 `planner.v1` 计划（没有 `candidate_scope`、项目 revision、事实证据原文与题目原文）不能用于面试，也无法就地升级：只能按当前配置重新生成并确认，旧计划保留供回看。

| 显式设置 `INTERVIEW_DATABASE_URL` | 使用指定数据库；仅 local 环境的 SQLite 自动迁移。 |
| `production` 或 `test` 环境，连接串留空 | 保持未配置状态，不自动回退到本地文件。 |

可通过 `INTERVIEW_DATA_DIR` 调整默认文件目录；相对路径按启动时的工作目录解析。SQLite 外键检查已启用，使用与 MySQL 相同的内容版本和元数据关系。备份本地数据时，停止服务后复制 `data/` 即可。


用户名和密码中的特殊字符需要 URL 编码。先单独创建使用 `utf8mb4` 的 MySQL 数据库，再显式执行：

```powershell

```

`.env`、虚拟环境与 `data/` 不进入版本控制。请勿将简历、题库、数据库凭据或模型密钥加入源码仓库。

## 题库 API

基础路径为 `/question-bank/questions`，完整请求结构导入 Apifox 后查看；`/docs` 保留为备用入口：

| 方法/路径 | 行为 |
|---|---|
| `POST /question-bank/questions` | 创建题目，保存第一份内容快照。 |
| `GET /question-bank/questions` | 分页查询；支持 `is_active` 和题干字面文本 `search` 筛选。 |
| `GET /question-bank/questions/{id}` | 读取当前内容、`revision` 和 `content_version`。 |
| `PATCH /question-bank/questions/{id}` | 编辑题干、答案、备注或启停；必须提供 `expected_revision`。 |
| `DELETE /question-bank/questions/{id}?expected_revision=1` | 逻辑删除，保留历史和关联元数据；普通接口不再返回该题。 |
| `POST /question-bank/questions/batch-delete` | 提交 `{id, expected_revision}` 列表（最多 100 项），原子批量逻辑删除；任一题不存在或版本不符则整体回滚，保留历史与来源引用。 |
| `POST /question-bank/categories/batch-delete` | 提交 `{id, expected_revision}` 列表（最多 100 项），批量删除空分类；任一分类不存在、版本不符或仍有未删除题目时整体回滚。 |
| `GET /question-bank/questions/{id}/versions` | 分页查看内容版本，新版本在前。 |
| `GET /question-bank/questions/{id}/versions/{version}` | 读取指定版本原文。 |

创建示例：

```json
{
  "question_text": "事务的原子性是什么？",
  "standard_answer_text": "用户自己的答案，可包含 Markdown 和代码块。",
  "user_notes": "需要复习的内容",
  "is_active": true
}
```

题干不能全为空白；答案和备注允许空字符串，内容不做自动裁剪、换行转换或润色。编辑时省略的字段保持原值，显式 `null` 会被拒绝。内容实际变化才增加 `content_version` 并原子保存快照；启停只更新 `revision`。旧 `expected_revision` 返回 HTTP 409，避免覆盖新修改。

创建请求可携带 `Idempotency-Key`（1–128 个英文字母、数字或 `_.:-`）。同一标识和同一请求只创建一次，重试返回 HTTP 200 和该题当前状态；标识用于不同内容或对应题目已删除时返回 HTTP 409。未提供标识的创建请求独立处理。元数据绑定具体内容版本，本阶段不提供 AI 元数据写入接口。

Markdown 接口同样可通过 `/openapi.json` 导入 Apifox：

| 方法/路径 | 行为 |
|---|---|
| `POST /question-bank/imports` | JSON 提交 `file_name`、原文 `content` 和可选 `strategy`，创建预览草稿（201）或复用已有批次（200）。 |
| `GET /question-bank/imports/{id}` | 读取候选题、提示与批次确认状态。 |
| `POST /question-bank/imports/{id}/confirm` | 提交 `selected_indices` 数组，以预览中的 `candidates.index` 为准；整批保存或安全重放。 |
| `GET /question-bank/imports/{id}/document` | 下载 UTF-8 来源文件，保留 BOM 与换行。 |
| `GET /question-bank/questions/{id}/source` | 读取来源文件信息、行号与原始段落；手工题或已删除题返回 404。 |

预览 API 使用 JSON 文本而非 multipart；客户端不提交本机文件路径。确认 API 仅接收候选序号，题干、答案与来源均从服务器保存的草稿读取。

## 后续讨论已确认的补充

以下是设计文档之后的用户确认，后续实现应遵循这些约束：

- 通用题使用用户原题，允许动态追问；追问只保存到场次，不自动写回题库。
- 目标时长是规划参考，到时允许继续，不强制结束；通过目标范围和有限追问避免无限提问。具体次数默认值尚未确定。

- 题库主要来自 Markdown Q-A 笔记；图片暂不识别，AI 不补写题干或标准答案。
- 模型优先 Qwen 系列，具体型号与接入参数后续确定。

Markdown 首版切分与预览行为见上文；更复杂的笔记格式后续按实际文件补充。设计稿中“时长是硬边界”“时间到结束”的旧表述后续需按上述确认同步。
