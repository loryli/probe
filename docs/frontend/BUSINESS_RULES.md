# 前端业务保护规则

本文是持续有效的业务约束，配合 [前端方案](README.md)、根目录 AGENTS.md 和后端契约使用。保护规则不表示每一项交互都已经实现或验收。

## 1. 变更边界

前端调整不得隐式改变事务、模型调用、取题规则、结束条件、资料保留或内容版本策略。业务变化需另行明确范围。默认由用户启动服务验收，不主动运行测试、检查、迁移或浏览器验证。

## 2. 全局不变量

| 编号 | 必须保护的规则 | UI 需要保留的表达 |
|---|---|---|
| G01 | 数据库是已保存业务数据的来源 | 输入草稿、等待结果、已保存记录分开；不以浏览器存储或演示数组替代 API |
| G02 | 用户原题、答案、笔记是用户资产 | 不自动补写、润色、摘要替换、trim 全部原文或改变未编辑字段的换行 |
| G03 | 原文按文本安全展示 | 保留 textContent/文本节点等做法；不得直接把资料传入 innerHTML。以后如需 Markdown 渲染需单独安全设计 |
| G04 | 写操作遵守 revision 和幂等约定 | 冲突保留草稿；结果未知先读取；相同操作不能因重绘按钮或刷新重新调用 |
| G05 | 读取不是生成，生成不是保存 | 页面载入、展开详情、切换 tab 不自动触发模型；人工确认入口保持明确 |
| G06 | 阅读与编辑明确分离 | 只读展示已保存记录；显式编辑和取消；切换记录、导航和关闭时保护实际未保存内容 |
| G07 | 资料中的指令不是应用指令 | 简历、笔记、代码、模型结果只作数据；不执行其链接、脚本或命令 |
| G08 | 隐私与日志边界 | 不将密钥、连接串、完整资料/模型正文写进日志、示例、设计稿或前端持久化存储 |

## 3. 题库与导入

依据：`frontend/src/views/QuestionBankView.vue` 与后端 `question_bank/`。

- 题干、答案、备注实际变化时追加内容版本；启停、分类变化不应被 UI 当作内容重写。题目编辑只 PATCH 实际改动字段。
- 分类管理、未分类、搜索、启停筛选、分页、本页勾选、批量移动与批量删除继续可用。「批量管理」入口常驻，进入后提供本页全选、已选数量、移动所选、删除所选和清空选择；翻页、筛选或退出批量管理清空选择。移动与删除提交每题 revision；不扩大成本页之外的隐含全量操作。提交中锁定操作区域，失败保留选择与草稿；删除涉及当前编辑题目时先确认丢弃草稿，不影响未删除题目的编辑内容。
- 分类管理弹窗可逐个删除空分类，也可「清理空分类」一次删除全部空分类：两者都是物理删除分类行，只允许删除没有未删除题目的分类；已逻辑删除题目的残留引用会被解除，题目本身、来源与已确认计划不受影响。
- Markdown 导入是选择文件 → 确定性预览 → 勾选核对 → 确认入库；预览不等于创建题目。保留题干、答案、提示、来源原文及下载入口。
- 图片标记保留但不识别，缺少答案不自动补写。不得为了统一阅读样式改动导入拆分规则；本次只修正「标题标记后的排版空行不计入答案正文」这一内容边界，已同步升级解析器版本（`markdown-v2`），旧批次按导入时的版本与原文保留。
- 阅读区与编辑区职责分离：编辑框始终是 Markdown 原文；答案、笔记与列表题干按有限 Markdown 子集渲染（标题、段落、列表、代码围栏、引用、分隔线、加粗、斜体、行内代码、`http(s)` 链接与反斜杠转义），由 Vue 组件生成节点，不使用 `innerHTML`，不解析 HTML、不加载图片。来源原文、导入预览与版本原文保持纯文本，便于核对。
- 同内容/策略/解析版本复用批次：草稿、或已确认且导入题仍存在时复用。已删除任意导入题后再次上传同一文档会创建新批次，旧批次、来源与删除历史保留；确认结果未知时保留锁定选择和“重试确认”，不能换选后新建重复题目。
- 查看历史和来源不覆盖当前草稿；删除题目是逻辑删除，保留历史引用，不暗示物理擦除。

## 4. 简历、项目与 AI 提取

- 对外模块名称为「简历」，项目经历在所选简历内管理，继续独立保存来源版本与人工核对结果。主流程为上传 PDF → 提取并核对文字 → 保存简历 → 明确点击 AI 提取项目 → 核对保存项目 → 创建面试计划。「粘贴文字建立简历」保留为次要添加方式，不与上传 PDF 并列成两个主入口。
- 练习方式只在面试计划中选择：题库练习无需简历；简历面试可使用已有简历，或前往上传新简历。题库、简历及练习空状态不再重复提供「只练题库」快捷选择；练习页无可用计划时引导去计划模块。
- 上传并核对后，用户可明确选择「保存并 AI 填写项目」；动作等待该来源版本的任务历史读完，不因读取中静默返回。历史读取失败时说明未发起新调用；未明确写出的技术栈等可选字段允许留空，不推断补齐。提取成功自动载入第一份项目表单，保存后继续核对下一项目；仅填草稿，不自动创建正式项目。核心表单是名称、技术栈、简介、多条描述；来源引用按需展开，不能把同一段正文与引用并排要求重复录入。

依据：`frontend/src/views/MaterialsView.vue` 与后端 `materials/`。

- PDF 原件、提取预览、人工修正草稿、已保存简历版本是不同对象。重新 OCR 或整理换行只返回草稿，保存后才形成简历版本。
- 「重新提取」必须是真动作：跳过提取缓存重跑一次识别，并用新结果覆盖同键缓存；只有重新上传相同字节的 PDF 才允许复用已有结果，且页面须明确提示命中缓存，不能把缓存结果当成二次识别。
- OCR 支持 auto/force/off；本地识别，首次可能下载引擎模型。不得把本地 OCR 与发送文字到 Qwen 混成同一个“智能识别”动作。提取质量配置（渲染 DPI、检测/识别模型档位、引擎输入上限）属于提取版本的一部分：改动必须升级提取版本使旧缓存失效，并在页面提示新的耗时预期（当前 `pdf-v5` 扫描页约 45–55 秒/页）。引擎输入上限必须与渲染像素上限一致，否则整页被压缩会让灰色小字整行漏检（`docs` 与 `pdf.py` 注释均已注明）。
- 项目固定引用具体简历版本；更新简历不自动重绑。事实引用必须匹配该版来源（匹配时忽略空白排版差异：换行、多余空格、全角/不间断空格，措辞仍须逐字同源，入库回填来源真实原文），无引用标为手工补充。UI 不隐藏来源版本，也不凭置信度显示“事实已验证”。
- 项目表单可从当前绑定简历版本的原文按段选取事实，原文同时作为内容与引用；纯确定性选取，不调用模型。没有可选取内容或未发现明显项目段落时提示并保留手动填写，不自动编造事实。
- Qwen 项目提取由用户明确触发，只处理指定已保存版本；产生持久化草稿。载入编辑、人工核对、逐候选确认后才创建项目，不能直接把候选当正式项目。
- AI 提取超时/不可用时保留失败记录，并提供「本地规则备选」与手工原文选取。备选不调用其他模型、不自动重试收费请求，只按章节/日期/标题生成单独候选，明确标注规则来源；经同一人工确认流程保存。模型改用原文行号，事实正文由服务端还原，不能把行号有效等同于事实归属或真实性已核实。
- 提取提交后接口立即返回 `running` 草稿，模型在服务端后台任务里执行；页面用单一轮询读取已保存草稿状态，只显示已用时间，不伪造阶段或进度百分比。用户可停止等待、离开页面或稍后点「读取本次结果」，后台任务继续，不重复调用模型。请求未决时保留请求标识并提供「读取本次结果」，明确失败后才允许新的付费调用。
- 提取进行中不显示「没有项目事实」空状态，避免与后台任务状态矛盾；候选为 0 时必须说明引用未匹配（核对已忽略空白排版差异，措辞改写仍会剔除）或简历未识别到项目段落，并引导手动选取事实，不把空结果包装成成功。
- 行号提取契约中，项目引用只定位标题，不能用标题的结束行限制全部事实。事实须落在本标题之后、下一个有效候选项目标题或后续履历分区之前；跨越已知边界的引用排除并提示，不能仅凭它在整份简历中存在就挂到本项目。技术栈为空只说明候选字段为空，不据此断言原文没有技术栈声明。零候选或全部已确认时，页面明确说明结果，不继续显示「准备填写」。
- 读取任务/刷新结果不重新调用模型；任务失败与收费请求重试有明确动作区别。确认重试不得重复创建项目。
- 简历和项目有独立草稿。保存一方、切换标签或更新列表，不能覆盖另一方未保存内容；格式整理的撤销入口和取消编辑行为继续可达。
- 现有资料 PUT 提交完整可编辑内容，重构不能随意改成局部请求；保留未改原文、revision 和原件关联字段。

## 5. Planner

- 先选择纯题库或简历项目。纯题库提交空简历 ID/版本、空项目范围及零额外追问，只冻结题库版本；不要伪造占位简历。无简历时也要提供可用题目列表。
- 项目模式继续要求具体简历版本、已核对项目，允许配合题库。确认计划后冻结范围不随后续编辑漂移。
- 追问额度区分自动（API `null`）、禁止（`0`）与指定上限；已确认计划仍使用原冻结额度。调整旧计划时，若历史输入为 `0` 而冻结结果实际有正额度，使用已保存的实际额度作为新配置，不误转成禁止追问。模型用请求内短引用，服务端精确映射，未知引用继续拒绝；引用字段可能含模型误写的资料正文，日志和错误仅展示格式合规的短标识或通用提示。失败后可主动选择原配置规则规划，不自动重试收费调用。

依据：`frontend/src/views/PlannerView.vue` 与后端 `planner/`。

- Planner 规划目标、优先级、来源、预算和追问约束，不输出锁定整场的固定题单。候选资料与目标依据不是“本场必问题数”。
- 所选简历版本、项目及事实、题目内容版本与候选范围固化；确认前检查资料变化。配置漂移、旧契约、生成失败不能通过更醒目的确认按钮绕过。
- 模型模式与本地规则模式分开；选择规则模式不产生模型费用。生成、读取已有结果、确认计划各自有独立状态。
- 调整已有计划的配置后重新生成形成新计划，保留历史；不能把“编辑配置”包装成覆盖已确认计划。
- 计划列表逐项提供删除，详情统一提供删除入口，包括失败且无结果的记录；沿用逻辑删除、revision 校验并保留已有场次与冻结资料。生成中的计划先读取完成或失败状态再删除，移除记录不被包装为取消模型调用。删除前读取当前 revision，确认后提交；提供历史分页，删除最后一项后回到有效页。
- `planner.v1` 可历史查看，新版运行契约需要完整资料依据。遇到不可用旧计划要解释并引导重新生成，不临时拼接最新资料冒充历史。
- 不把模型提示、置信度和系统校验混成一种成功标记；保留引用明细和失效原因。运行时短摘要不替代完整原题。
- 生成时不把标准答案和笔记混入规划模型输入；runtime 冻结资料包含答案，后续展示及模型消费保持用途区分。

## 6. 面试、流式状态与恢复

依据：`frontend/src/composables/useInterview.ts`、`frontend/src/api/interviews.ts` 与后端 `interview/`。

- 场次从可用已确认计划创建，冻结运行依据；进度 active/paused/completed 及 current_turn/pending_turn_id 由服务端确定。
- 新建简历面试先「自我介绍 → 项目介绍 → 技术问答」；纯题库直接进入原题。服务端 `phase` 控制阶段，轮次 `stage` 标记开场类型；介绍沿用回答先保存、重复提交保护、暂停恢复与跳过流程。开场不调用模型、不计入目标问数或追问额度；项目介绍完成后才生成技术问题，第一目标优先在冻结范围内衔接介绍中提及的项目。介绍只作为本场未核实自述，复盘不能引用无目标的介绍轮次作为技术达标证据；旧场次缺少阶段字段时按技术问答兼容，不插入开场。
- 一次聚焦当前问题；题库原题与项目事实来源继续可追溯；问题呈现不改成无来源的通用聊天提示。
- 回答先落库，随后生成下一步。`ack` 到达才可说明回答已保存；下一问通过校验、动作约束并落库后，才以 `delta` 推送实际文本，不提前转发待审核 `say`，不承诺首 token 逐字显示。场次终态仍以 `state` 或回读为准。
- 未确认保存的回答遇到失败应保留；已保存而生成失败要显示恢复入口，不能要求用户重新回答或诱发重复保存。
- EventSource/轮询恢复的是场次状态，不承诺逐字事件永久重放。不能把前端流气泡永久保留为数据库记录。
- 保留暂停、继续、跳过目标、结束和继续生成。跳过的对象当前是**目标**；不能只改文案成“跳过本题”。跳过/结束涉及丢弃未提交草稿的说明和确认不能消失。
- 当前 busy/流式期间有控件禁用策略。若希望生成中仍可暂停/结束，需单独核对后端并发语义；本次不通过解除 disabled 改变它。
- 辅助面板默认关闭，主动展开参考答案与笔记符合当前练习行为；保留草稿、选区和返回焦点。是否记录查看答案、增加考试模式或影响评价属于待确认新需求。
- 参考资料只用本场固定版本；引用接口失败时解释并允许重读，不能默默回退为今天的答案。
- 开始、回答、模型失败后的重试与复盘调用保持明确。视觉组件初始化或重新进入页面不得自动补发付费请求。
- 练习页「记录管理」提供批量删除历史场次：勾选、危险确认、删除后刷新列表。删除是物理删除，连同全部轮次、目标进度与整场复盘一起移除，不可恢复；已确认计划不受影响。进行中的场次不可选，需先结束或暂停；删除当前打开的场次时清空未提交草稿并回到无场次视图，不留下指向已删场次的界面状态。

### 时长规则：已按产品约定统一

项目约定是「目标时长仅作参考，到时不强制结束」；此前 `interview/service.py` 的 `BUDGET_GRACE_SEC=300` 与超出宽限后在回答结束时自动收尾的实现与之冲突，现已移除该收尾分支与常量。

当前行为：目标时长只用于节奏参考与剩余时间展示；超出目标 60 秒后不再新增追问（有限追问边界）。混合面试中，单目标用满自身预算且还有其他未完成目标时，下一问让位给按题源预算份额挑选的其他目标；被让位目标保持待考察、剩余基础题稍后回来问完，不因到时丢题或强制结束。纯题库模式不让位，按顺序问完所选原题。场次由用户主动「结束练习」，或在所有考察目标完成后自动结束。UI 不得新增倒计时强制结束或暗示到时会自动收尾的文案。

### 追问额度与题库推进

- 追问额度只由服务端计算（`InterviewService._followup_allowance`）：取「目标上限、全场总额度、每目标上限」三者最小值；目标与全场预算用尽时返回 0，决策提示与落库共用同一结果，模型无法通过「同目标续问」绕过。
- 纯题库始终禁止追问。混合面试的题库原题至多追加一次追问：回答追问后，本轮追问额度直接为零，不能把先前原题未用的额度集中到同一道题。题库目标同时要求**追问数 ≤ 已问原题数**，并受目标、全场和时间预算约束。不再追问时推进冻结原题与游标，或在目标已覆盖时切换目标；不能用模型自拟普通续问绕过。项目目标仍受目标额度与目标时间预算约束。
- 模型要求追问但服务端不放行时，落库的必须是基础题（原题或下一道骨架题），不得把模型那句改成普通问题保存；服务端会记录 `follow_up rejected` 日志，含额度、已用次数、游标与预算。
- 暂停不计入总时长与目标预算（`interview/timing.py` 的 `active_seconds` 用 `paused_seconds` 扣减），恢复不损失追问额度。
- 预算让位也只由服务端决定（`_apply` 的 `defer_for_budget` 分支 + `_next_pending` 的 `exclude` 参数）：混合面试中未判定覆盖的目标用满自身预算、仍有基础题且存在其他未完成目标时，下一问切到按题源份额挑选的其他目标，不把预算切换误记成覆盖。恢复该目标时继续原有基础题进度，模型不能重写已问过的基础题。基础题耗尽的目标不再被调度重新激活；仅剩未耗尽的该目标时照常继续。

## 7. 复盘与未来能力

- 纯题库的“只问原题”约束由服务端保证，不只是文案；不展示模型自拟下一问、不截短已选原题。回答反馈与出题分离，规则练习无需模型配置；复盘只使用已保存问答。

- 当前整场复盘按用户点击生成，报告读取不触发新生成；报告失败仍保留问答。原标准答案是参考，不是逐字背诵的唯一真值。
- 当前有整体文字标签、逐目标覆盖/不足、弱项、建议与轮次关联。不得擅自转换为综合分数、排名、确定能力画像或自动更新长期记忆。
- “存在轮次关联”不等于所有判断均已核实。呈现保留模型观察属性，不通过绿色勾号把推测变成事实。
- 语音将共用场次、目标、轮次和控制的领域语义，但录音、转写、播报、打断和错误恢复仍需独立设计。不能把未来语音状态伪装成现有接口已支持的功能。
- 逐轮后台分析、长期记忆确认与语音不在本轮已实现能力中；不设计可点击的假入口。

## 8. 后续每页的保护清单

2026-11-12 文字闭环恢复约定：

- 提取记录按保存的简历版本读取，页面恢复只 GET 原任务；同版本已有运行任务时服务端返回该任务。停止等待不取消后台任务；失败重新提取是用户明确触发的新调用。原请求尚未落库时，可用同一请求标识手动重试提交。
- 提取草稿读取携带已有数据库字段 `expires_at`，列表可按 `source_version` 过滤。读取失败连续三次后停止页面等待，保留原任务入口；切换资料或离开后旧轮询结果不回写新工作区。
- 编辑候选时固定候选草稿 ID、revision 和来源版本，不把当前浏览的另一次提取任务作为保存依据；修改内容撤销「已核对」。没有依据的候选仍排除，原文匹配规则不放宽到改写事实。
- 面试回读同一问题保留编辑内容。问题已变化时，未提交文字单独显示，禁止自动作为新问题答案提交；此草稿仅在当前页面内存中保留，离开/刷新仍需丢弃提示，不代表已保存到数据库。
- 状态恢复不自动重跑模型；同一步恢复等待有时间边界，超时显示读取/手动继续入口。开场、续接和报告请求允许等待模型调用时限，超时仍按结果未知处理。文字流解码必须保留跨网络分块的 UTF-8 字符。
- 项目进入计划时显式携带简历版本；已确认计划仍只读取冻结快照。复盘轮次链接只定位已保存的真实回答，不把生成文字当作证据。

交付前由实现者逐项说明，运行验收默认交给用户：

- 页面现有业务入口有无缺失，改变位置后能否找到；Vue 路由、组件事件、模块导入和条件渲染是否保持对应。
- 已保存记录和草稿是否分离；关闭/离开/切换/取消后是否有正确提示；409 后是否保留输入。
- 点击产生的是读取、保存、确认还是模型调用；按钮忙碌、禁用、重试是否与真实状态一致。
- 长原文、代码、换行、历史、来源和版本是否可读可达；删除、分类移动和启停语义是否准确。
- 提交回答后的保存确认、流中断、状态回读、继续生成和报告失败是否分别可解释。
- 键盘焦点、快捷键、对话框/抽屉关闭、小屏滚动与缩放是否列为用户体验项。
- 如遇接口不足或业务冲突，记录独立问题，不为完成视觉稿擅改数据结构、后端行为或产品规则。
