# 前端开发方案

本文件是前端技术、目录与视觉的唯一方案入口。业务不变量见 [BUSINESS_RULES.md](BUSINESS_RULES.md)，项目运行说明见 [根目录 README](../../README.md)。旧原生页面和旧视觉设计已删除，历史决策通过 Git 查阅。

## 技术与运行

- Vue 3 Composition API、TypeScript、Vite、Vue Router；当前不引入全局状态库、服务端渲染或重型组件平台。
- 开发时 FastAPI 监听 `127.0.0.1:8000`，Vite 监听 `127.0.0.1:5173`；前端页面入口是 `/`，API 由 Vite 转发。
- 构建产物为 `frontend/dist/`。从仓库源码运行 FastAPI 时，`/app/` 提供 Vue 页面，`/frontend-assets/` 挂载整个构建目录，保留 Vite 输出的 `assets/` 子目录。
- 后端根路径 `/`、`/materials`、`/planner`、`/interview` 只做页面地址重定向，不提供旧页面。`/materials/resumes` 等 API 路径不受影响。
- 未构建时页面返回 503 和启动说明，API 继续可用。构建后需重启后端以挂载静态资源。Python 包不携带前端构建产物，部署需同时准备源码布局和构建目录。
- npm 依赖由 `frontend/package.json` 与 `package-lock.json` 管理，使用 `npm ci` 安装；生成目录和缓存不提交。

## 源码目录

```text
frontend/
  index.html             Vite HTML 入口
  vite.config.ts         API 代理与构建资源前缀
  src/
    main.ts              路由与固定样式加载顺序
    App.vue              共用品牌、导航与外框
    types.ts             面试领域前端类型
    api/
      common.ts          普通 JSON 请求、错误与幂等头
      interviews.ts      面试 API 与 POST SSE 解析
    composables/
      useInterview.ts    场次状态、作答、恢复、控制与复盘
    views/               题库、资料、计划、练习四个工作区
    styles/
      base.css           全局变量、基础控件与练习页样式
      workspace.css      共用工作区外框、标题、侧栏与控件
      question-bank.css  题库专用样式
      materials.css      资料专用样式
      planner.css        计划专用样式
```

按实际复用需要抽取组件和类型，不预建空业务目录。页面仅操作后端 API；数据库是已保存业务资料的来源。不要将业务持久化移到浏览器存储，不插入演示数据。

## 统一视觉

以「练习场」页面为基准：深墨色文字、灰绿背景、白色内容区和少量黄绿色强调。四页共用 `App.vue` 中的品牌和完整导航，路由决定当前项；不再另写页头或品牌。

全局字形、颜色和面板尺寸由 `styles/base.css` 的变量管理。工作区标题、按钮和侧栏由 `styles/workspace.css` 管理；页面专用样式限定于对应根类，避免同名选择器影响其他页面。样式统一从 `main.ts` 加载。不同任务可以采用不同内容布局，但外框、导航、控件语义和视觉层级应保持一致。

当前 `base.css` 仍包含练习页专用样式；后续有实际改动时再分离，避免为目录美观引入无用途抽象。具体视觉和窄屏表现仍需用户实际体验，不把源码实现视为验收通过。

## 工作区职责

| 页面 | 主要任务 | 需要保留的语义 |
|---|---|---|
| 题库 | 检索、分类、原文编辑、历史、Markdown 导入与来源 | 编辑只提交变化字段；导入先预览再确认 |
| 资料 | PDF/OCR 草稿、简历版本、项目事实、AI 候选核对 | 原件、草稿与版本独立；候选需人工核对后保存 |
| 计划 | 固定材料版本、范围、目标与预算、确认与调整 | Planner 不生成固定题单；调整形成新记录 |
| 练习 | 文字问答、控制、恢复、历史与复盘 | 场次从可用已确认计划创建；以服务端状态为准 |

## 实时与调用边界

回答提交使用 Fetch POST SSE；`ack` 表示回答已保存，`delta` 只是临时显示，`state` 或重新读取场次决定最终状态。EventSource 用于恢复状态，不重放已流过的文字。普通 JSON 请求不能吞掉 SSE、PDF 二进制、204 和各自超时规则。

创建、回答、计划生成、AI 提取与报告沿用后端幂等约定。结果未知时读取原任务或复用原标识，不自动重发收费调用；revision 冲突保留草稿。读取、生成、核对和保存应是清晰独立的动作。

现有时长实现与“不强制到时结束”的产品规则存在待确认差异，见业务规则中的时长冲突说明；目录清理不改变这一业务逻辑。
