# 产品需求文档（PRD）

## 1. 产品概述

**暂定名称：** Personal AI Interview Coach（个人 AI 面试教练）

**首发岗位：** 大模型应用开发、AI 全栈。

**首发交互：** 第一版文字面试，语音在后续阶段针对延迟进行优化后接入。

**一句话描述：** 帮助个人基于自己的简历和题库进行逼真的模拟面试，并用可追溯的证据复盘薄弱点。

### 用户问题

- 自己整理的答案容易停留在背诵，缺少追问和检验。
- 项目经验需要根据简历被连续追问，固定题单无法模拟这种过程。
- 练习记录分散，难以看出反复出现的薄弱点。
- 面试时分析太慢会破坏真实感，面试后又需要更深入的评价。

### 产品目标

1. 用户可导入简历、维护项目事实，并在每场面试前生成面向大模型应用开发 / AI 全栈岗位的可调整考察计划。
2. 用户可维护自己的通用问题和答案；AI 能辅助分类/标注而不触碰其原文。
3. 面试过程在目标和预算约束下自适应追问，不因慢速分析停顿。
4. 面试结束后得到有回答证据支撑的复盘，并逐步积累结构化历史。

## 2. V1 范围

### 核心模块

1. **个人资料与简历**：上传/粘贴简历；离线解析工作经历、项目、技术栈、职责、量化结果和待核验主张；用户可校正解析结果。首发目标覆盖 RAG、Agent/工作流、模型应用工程、后端交付与 AI 全栈相关能力，具体问题仍从简历事实和用户题库出发。
2. **个人题库**：创建、编辑、导入、删除问题与标准答案；原文和 AI 元数据分离；允许用户覆盖元数据。
3. **面试规划**：选择岗位/级别（可自由配置）、时长、难度、项目题/通用题时间比例、通用题范围、是否参考历史薄弱点；输出目标和时间预算供确认。
4. **模拟面试**：第一版为文字对话；按 Planner 选择来源；以回答为依据动态追问；支持继续、跳过、暂停、结束。会话接口预留未来语音适配。
5. **面试记录与复盘**：保存问题、回答、来源、时间、追问链和引用证据；面试后生成摘要、维度观察、待补知识点和建议练习项。
6. **结构化记忆**：保存有来源的观察和知识点掌握证据；V1 仅记录，不呈现为确定的完整能力画像。

### V1 不做

- 多用户账户、组织、权限管理和共享题库。
- 自动撰写或重写标准答案、自动代替用户修改题库原文。
- 复杂多 Agent 编排、知识图谱、招聘匹配、资料爬取。
- 自动投递简历或外部系统集成。
- Planner 预先生成并锁定整场问题清单。

## 3. 核心用户流程

### 首次准备

上传/粘贴简历 → 离线解析 → 用户校正项目和事实 → 导入或手动维护通用题库 → AI 生成元数据 → 用户确认/覆盖标签。

### 开始一场面试

选择岗位与时长 → 设置难度、题源比例、题库范围和历史薄弱项 → Planner 生成目标、预算、来源选择策略 → 用户预览并开始。

### 面试进行中

Agent 开场 → 提出当前目标的第一个问题 → 接收回答 → Fast Path 决策追问/推进/换源/结束 → Background Path 并行分析 → 用户可暂停、跳过或结束。

### 面试后

等待 Offline Path 整理证据 → 查看逐题反馈和整场摘要 → 选择是否将结构化观察纳入长期记录 → 从复盘建议开始下一次练习。

## 4. 功能需求与优先级

| ID | 需求 | 优先级 |
|---|---|---|
| P-01 | 用户能维护简历版本和结构化项目事实；原始简历保留。 | Must |
| P-02 | 简历解析离线执行，输出可人工校正的结构化结果。 | Must |
| P-03 | 用户题目/答案原文与 AI 分类、标签、难度分开存储。 | Must |
| P-04 | AI 元数据可审核、重试、编辑；仅元数据更新不产生原文变化。 | Must |
| P-05 | Planner 输出考察目标、预计时间预算、题源比例和边界，不输出固定问题列表。 | Must |
| P-06 | 项目问题来自已确认的简历事实；通用问题来自用户启用的题库。 | Must |
| P-07 | 同一个实时 Agent 处理两类问题和后续追问。 | Must |
| P-08 | Fast Path 输出结构化决策；超时有可继续对话的降级路径。 | Must |
| P-09 | 异步分析失败可重试，不影响当前轮次。 | Must |
| P-10 | 每轮记录原始回答、转写状态、问题来源和模型决策。 | Must |
| P-11 | 面试结束后生成引用回答证据的复盘。 | Must |
| P-12 | 用户可以删除场次及关联转写/记忆数据。 | Must（依数据部署决策细化） |
| P-13 | 文字输入/输出是 V1 主路径；架构允许后续接入语音而不重写会话状态机。 | Must |
| P-14 | 按弱项、标签和难度对题库进行筛选。 | Should |

## 5. 产品规则

- 题库问答采用「用户内容 + AI 元数据」双层模型；重跑 AI 标签不能改变题目或答案的原始文本。
- 评估答案时，用户标准答案可作为其自定义参考，但不能当成唯一真值；至少区分关键点覆盖、技术准确性、表达清晰度，并提供证据。
- Planner 的时间预算是软约束。用户回答时长、暂停和追问会改变实际分配；Agent 需要在剩余时间内优先完成高优先级目标。
- 题源比例按时间近似控制，而非为了达到百分比强行打断对话。比例容差与最小题目数待实际使用后校准。
- 项目事实不足时，Agent 应询问澄清或选择通用题，不得编造用户项目细节。
- 用户可跳过问题、请求提示、暂停或结束；这些显式控制优先于自动调度。
- 对能力和经验的结论必须标注为观察/推测，并链接到具体回答证据。

## 6. 非功能需求（V1 目标，数值待技术栈与模型确认）

- Fast Path 使用短上下文、结构化输出和明确超时，目标是尽量让下一轮感觉连续；具体 P95 延迟待选型后确定。
- 云端模型可用于 V1；不将 API 密钥写入数据库或日志。简历、面试记录和题库需具备删除与导出能力。
- AI 输出均经过 schema 校验；无效输出重试一次，仍失败则使用安全回退。
- 异步任务必须幂等，有状态可观察，可重试；用户可看到失败而不是静默丢失。
- 关键数据可导出；删除场次时按外键/关联规则处理转写、分析结果及生成的记忆引用。

## 7. 成功指标

V1 先验证使用价值，不把模型分数当产品成功：

- 从准备到开始模拟面试的流程无需手动整理固定面试题单。
- 同一场面试中能够出现与项目细节相关的连续追问。
- Planner 的目标和实际问题来源可解释，用户能调整计划。
- 题库 AI 元数据处理后，用户原题和原答案逐字不变。
- 每场完成的面试可回放/复盘；复盘中的重要判断有回答证据。
- 用户愿意在不同日期重复使用，并能从历史记录找到可行动的薄弱点。
