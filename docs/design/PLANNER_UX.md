# 面试计划 UX

状态：待确认方案；仅交互设计。目标：先选清楚训练依据，再理解计划，确认后自主进入面试；不把所有配置放进同一个长表单。

## 1. 列表、详情和创建是三个视图

- **计划目录**：紧凑纵向记录，显示方向、资料版本、预计时长、生成方式、状态、创建时间；主动作“新建计划”。不做大卡片瀑布流，不默认选中一条历史并开启编辑。
- **计划详情**：正文宽约960px，摘要与状态 → 题源预算 → 目标列表 → 资料范围/提示。返回目录保留页码；原列表不长期挤占结果阅读宽度。目录按现有分页，不承诺新搜索和状态过滤接口。
- **创建/调整配置**：取代目录为分步工作流。桌面左侧紧凑步骤导航，右侧当前步骤；中小屏顶部步骤条。调整已有计划会生成新记录，原计划不改。

## 2. 四步创建

| 步骤 | 主要内容 | 校验/动作 | 数据状态 |
|---|---|---|---|
| 1 训练依据 | 简历、具体版本、已核对项目及事实数量 | 选择版本后刷新对应项目；允许只做题库题，但仍遵守当前计划必须绑定简历版本的契约 | 仅前端配置草稿 |
| 2 题库范围 | 启用题目候选、勾选数、随机重选、全不选 | 保持候选显示顺序，随机决定选哪些；当前最多40道，项目最多8个；题源至少有一种可用材料 | 仅前端配置草稿 |
| 3 节奏与方向 | 方向、预计时长、项目时间比例；高级项：追问上限；模型/规则生成方式 | 汇总资料数量与版本；明确时长为参考、比例按时间；确认点击“生成计划”才提交 | 提交后产生服务端任务 |
| 4 预览与确认 | 目标、预算、引用、警告 | 核对后“确认计划”；或返回配置调整并生成新计划 | ready → confirmed，服务端成功为准 |

已有简历但无项目时步骤1解释可选择题库训练；完全没有简历时当前接口无法创建纯题库计划，明确引导“准备简历”，不能把隐藏简历字段视为支持跳过。此限制若需放宽另立业务需求。

步骤1–3的“下一步”只校验和移动视图，不写库、不调用模型。可回到已访问步骤并保留本页草稿；跳往尚不满足前置条件的步骤时指出缺项。刷新或离开可能丢配置，显示未保存提示，不显示伪造的“已自动保存”。

第4步返回修改时，旧结果保留为只读；标明“配置已变化，请重新生成”。不能只修改预算数字后确认旧结果，也不允许直接编辑模型目标为已保存计划。

## 3. 题库选择的效率

题干候选是紧凑列表，说明当前抽样范围与数量。沿用已存在的启用题池和随机40道能力，不承诺按AI标签/难度检索或新的服务端分页。长候选列表可用局部滚动；选中总数和“随机重选/全不选”固定在当前区域顶端。

随机重选前若有手工调整，提示将替换本次选择；确认后重新抽取。切换步骤不重新随机。取消随机确认保留原选择。跨步骤返回时保留选择和列表位置。

## 4. 计划预览的信息优先级

```text
计划方向 · 简历 vN · 待确认
预计45分钟 / 项目与题库时间比例 / 追问边界
重要失效或材料不足提示（若有）
考察目标
  主题 · 来源 · 优先级 · 建议时间
  可观察证据与完成条件
  [查看引用依据]
资料范围（候选，不是固定题单）
[模型提示：未经核验] [调用详情]
[调整配置]                                [确认计划]
```

目标列表用分隔条目表达先后阅读顺序，不展示为锁定提问序号。候选40道不表示必须问40道，目标依据覆盖率不表示模型考核成绩。预算合计与实际比例由服务端结果提供，若因资料不足或最小时间调整，紧邻预算解释原因。

引用展开显示固定版事实/原题及手工补充来源，不用模型短摘要替代依据。模型自评、系统校验、产品规则分区展示；token、prompt/schema版本等放在调用详情，不占主要阅读区。

## 5. 确认与启动面试

“确认计划”只确认，不创建场次。成功后主动作变为“用此计划开始面试”，次要为“返回计划记录/调整配置”。进入面试开始页带入该计划是**拟新增前端导航上下文**：需读取并校验计划ID，不能仅凭URL判定可用，更不能自动创建场次或调用模型。

面试开始页再显示计划摘要与模型/规则出题方式，由用户点击“开始面试”后创建场次、生成首问。这样确认计划可独立完成，也避免“确认并开始”隐藏一次额外收费调用。

```mermaid
flowchart LR
    A[选择简历版本与项目] --> B[选择题库候选]
    B --> C[设置方向与节奏]
    C --> D[明确点击生成计划]
    D --> E{生成结果}
    E -- 失败 --> C
    E -- 就绪 --> F[预览目标和依据]
    F -- 调整配置 --> C
    F --> G[确认计划]
    G --> H[面试开始页带入计划]
    H --> I[用户选择出题方式并开始]
```

## 6. 状态、空态和恢复

| 情况 | 显示与动作 |
|---|---|
| 无计划 | 目录起点简短说明与新建主按钮，不铺空详情栏 |
| 无可用简历 | 步骤1解释前置条件，进入资料工作区；离开前告知草稿不会持久保存 |
| 无已核对项目 | 引导核对项目，或保留题库题路线，不伪造项目依据 |
| 无启用题目 | 返回题库启用，或只选有事实的项目；不自动生成通用题 |
| 生成中 | 显示资料已提交、等待时间、读取结果入口；锁定会改变本次请求含义的操作 |
| 超时但结果未知 | 保留request_id，先读取本次结果；读取不收费，不自动创建第二任务 |
| 明确失败 | 保留配置、原因，用户可改规则模式或显式重新生成 |
| ready | 预览与确认可用；配置变化后确认不可用并说明 |
| 引用失效/409 | 保留结果和输入，指出资料变化，要求重新生成；不自动加载新事实代替旧事实 |
| 旧契约 | 历史可读；确认/开始不可用，解释重新生成理由 |
| confirmed | 固定记录，可开始面试或复制配置重新规划；“调整”不修改已确认内容 |
| 列表读取失败 | 保留已打开详情，局部重试；不把空列表当成无计划 |

## 7. 响应式与滚动

目录、详情使用页面滚动；桌面创建左侧步骤导航sticky，当前步骤随主文档滚动。仅候选选择列表允许独立滚动。<900px步骤条简化为“第2/4步 · 题库范围”，另有可展开步骤目录，不用四个窄标签挤满一行。

底部“上一步/下一步/生成”随步骤明确变化；粘性按钮区为内容留底部空间，不覆盖错误或手机键盘。返回步骤焦点落到步骤标题，校验失败落到首个问题字段；不将焦点移动到隐藏步骤。预计时长、追问上限等保持原有限制，不借重设计改变默认值。
