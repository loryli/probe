# 前端选型与体验方案

日期：2026-11-10。状态：选型已采用，四工作区实现已接入；具体页面需由用户体验后继续修订。本文取代上一轮原生前端视觉和页面布局建议；不更改后端 API，也不代表本文列出的语音能力已经实现。

## 1. 调查结论：后端当前能支持什么

本次阅读了 `interview/`、`planner/`、`main.py`、实时面试数据流、AI/API 草案、业务保护规则和当前模拟面试交互文档。后端目前有计划、文字场次、回答保存、实时决策、场次控制和整场报告的可用闭环；逐轮后台分析和记忆候选尚未落地。

### 文字面试契约

| 能力 | 当前实现语义 | 前端含义 |
|---|---|---|
| 开始 | `POST /interviews` 依据已确认计划创建场次，`request_id` 幂等；首问可能在开始结果阶段生成 | 开始按钮进入真实等待；重复请求用原标识读取同一场次，不重复开场 |
| 回答 | `POST /interviews/{id}/answers/stream` 先提交并保存回答，再以 SSE 返回 `ack`、`delta`、`state` 或 `error` | 收到 `ack` 才标为已保存；`delta` 是临时流式呈现；以最终 `state` 或重新读取场次作为落定状态 |
| 断线 | 后台决策可继续；刷新后重新读取场次并订阅事件，但不重放已发出的全部 delta | 展示“回答已保存，正在恢复下一步”等确定状态，不能将未落库的气泡冒充历史记录 |
| 重试 | `POST /interviews/{id}/retry` 恢复下一步生成；模型失败不自动收费重试 | 重试必须是用户可见的单独动作，保留当前问题、回答及保存确认 |
| 暂停/继续 | 独立控制端点，提交 `expected_revision`；迟到决策被丢弃 | 场次状态以服务端快照为准；继续后可能需要手动重试下一步 |
| 跳过/结束 | 跳过当前**目标**，不是仅跳过当前题；结束保留问答 | 文案明确说明影响对象；未提交回答离开前按实际规则提示 |
| 复盘 | 结束后用户触发 `POST /report`；读取和生成分开，失败可重试 | 报告页显示生成状态和失败恢复，不阻塞场次记录读取 |
| 模式 | 当前为模型模式或规则模式 | 明确展示模式差异；规则模式不是模型能力已就绪的替代标签 |

现有时长实现存在待产品确认的冲突：项目约定要求目标时长不强制结束；服务端有 300 秒宽限后收尾逻辑。UI 设计不得掩盖或擅自解决此冲突，任何倒计时与结束措辞均需保持为待确认项。

### 语音的设计边界

当前没有录音、转写、音频流或播报接口。已有设计明确语音未来可复用场次、目标、轮次和控制等领域概念，但采集、转写、播报、打断、低置信度校正和断线恢复需要独立方案。AI/API 草案建议届时再评估 WebSocket/WebRTC，不能据此视为协议已定。

因此新前端应把“练习会话流程”与“输入/输出通道”分开组织：共享计划、当前目标、场次状态、历史轮次与复盘入口；文字通道负责文本编辑和 SSE；未来语音通道负责麦克风权限、录音状态、转写草稿、确认、播报和打断。只有后端契约、录音权限和错误恢复设计完成后，才呈现可用语音入口。

## 2. 前端技术选型

### 决策：Vue 3 + TypeScript + Vite

采用 Vue 3 Composition API 与 `<script setup lang="ts">`，Vite 独立开发和构建，Vue Router 承担工作区与对象详情路由。首期不引入服务端渲染、Nuxt、全局状态库或重型组件平台。组件库不先定：先确定视觉语言，再评估是否只引入可访问性与复杂交互有明确收益的控件。

选型理由：

- 现有产品是单用户工作台，以表单、长内容、列表、抽屉和状态转换为主；Vue 的单文件组件让页面结构、类型化状态和样式局部边界容易共同维护。
- 现在的页面 JavaScript 把 DOM 操作、副作用、渲染和大量固定 ID 绑定在一起。组件化迁移可逐页收敛，不必重写已经工作的 FastAPI 领域服务。
- TypeScript 的联合类型适合把 `active / paused / completed`、`ack / delta / state / error`、草稿和已保存等互不等价状态写清楚，避免只靠按钮 busy 标志表达业务状态。
- Vite 支持独立开发端口和 API 代理；生产产物可由现有 FastAPI 静态资源入口托管，保留本地启动一次服务的目标。
- SSE 是标准 Fetch/ReadableStream 交互，不要求引入特定实时框架。答案流继续使用 Fetch POST + SSE body reader；GET 事件监听可继续用 EventSource。

框架文档依据：Vue 官方文档的 TypeScript 单文件组件模式；Vite 官方文档的 `server.proxy` 与 backend integration 指引。框架选择是基于本项目形态的工程判断，不表示 Vue 在所有前端项目中普遍优于 React。

### 建议工程边界

```text
frontend/
  src/
    app/          路由、导航壳、启动状态
    shared/       API 错误、请求、通知、确认、基础控件
    domains/      question-bank、materials、planner、interview
    interview/    session state、text transport、future voice adapter boundary
```

上述是职责建议，不要求照此精确建目录。领域 API 客户端、视图和局部状态靠近各自业务；跨页只抽取真正重复且行为一致的能力。面试实时传输应单独封装，普通 JSON 请求层不能吞掉 SSE、binary PDF、204 与各自超时规则。

### 开发和运行方式

- 开发：Vite 在单独端口运行，转发现有后端路径；为减少迁移期改动，首阶段代理 `/question-bank`、`/materials`、`/interview-plans`、`/interviews`、`/health`、`/ai` 等既有根路径，不强行新增 `/api` 前缀。
- 生产：Vite 输出带哈希静态文件；FastAPI 挂载构建目录，API 路由优先匹配，工作区路由返回 SPA 入口。HTML 不缓存或短缓存，带哈希资源可长期缓存。需确保 `/openapi.json`、健康检查、API 404 不落入 SPA fallback。
- 启动：开发者开发前端时同时运行两个进程；普通用户使用构建产物时仍只启动 FastAPI。
- 依赖：Node 工具链作为开发依赖；前端锁文件需在依赖安装时生成并纳入版本控制（当前仓库尚无 `package-lock.json`）。Python 依赖不因前端框架改变。打包/发布流程需确保干净检出后能重建静态产物，产物不提交版本控制。

## 3. 产品信息架构

目标是个人面试训练工作台，不做数据仪表盘或聊天机器人首页。全局导航围绕真实工作区：**题库、资料、计划、练习记录**。记录列表提供恢复和回看入口；进行中的场次可从记录进入。无需强迫用户每次从简历开始走向导。

```
题库 ─┐
资料 ─┼─> 面试计划 -> 开始练习 -> 场次过程 -> 整场复盘
历史 ─┘                                      └-> 再次练习/回到资料
```

不把用户已有资产重复包装成评分卡。首页可用轻量“继续最近场次 / 新建计划 / 最近练习”呈现入口，但先不引入统计仪表盘、自动推荐和新业务写入。

## 4. 四个工作区的新版体验方向

旧文档中的具体三栏、步骤向导、色板和固定面板尺寸全部作废。下面是任务定义与体验目标，布局需要在视觉稿中重新表达。

### 题库：快速查找，舒服地读完

- 首屏先让用户找到题目：搜索、分类、启用状态及结果数量清楚可见。
- 阅读视图是主状态，长答案、换行和代码有舒适阅读宽度；编辑是明确切换后的工作状态，不用大 textarea 伪装只读内容。
- 分类管理、批量移动、导入预览、原文来源和历史放在与对象相邻的操作中；导入确认前可审阅选择，失败时保留选择。
- 视觉特征：以清晰的内容索引和正文为中心，避免每题都套厚重卡片。

### 简历与项目：建立可信证据链

- 页面明确区分 PDF 原件、提取预览、修正草稿、已保存版本、AI 候选、已核对事实。
- 项目事实与“简历版本 / 原文引用 / 手工补充”在同一视线范围；用户可从事实打开对应依据。
- 上传、OCR、解析、保存与 AI 提取是不同流程，各自显示真实阶段、失败原因和恢复动作。
- 视觉特征：像资料工作台与证据校对界面，优先呈现来源关系，不能用 AI 置信度代替人工确认。

### 面试计划：先理解输入，再判断结果

- 已保存计划、配置草稿、模型生成中、规则模式结果、待确认和已确认计划明确区分。
- 创建按任务顺序组织输入；只有最终明确动作会调用生成。结果先呈现目标、来源依据与时间预算，技术契约和细节可展开。
- 调整配置会形成新计划；历史结果可读，但不能被新配置伪装成当前结果。
- 视觉特征：减少配置表单的压迫感，强调“这些材料将支撑哪些目标、如何分配时间”。

### 模拟面试：一个专注的作答空间，辅助信息随需打开

- 当前问题与回答编辑器是屏幕的主要焦点。目标进度、剩余预算、回答状态和控制构成紧凑状态栏，不做第二套仪表盘。
- 问题、追问和回答按轮次形成清晰记录；当前临时流与已保存轮次视觉不同。回答保存后及时保留“已保存”，生成中显示真实等待，不以虚假百分比表示进度。
- 参考答案、笔记、简历事实和目标进度属于辅助信息，桌面可以侧栏或覆盖面板呈现，小屏切换为完整的辅助视图并可明确返回原回答位置。
- 暂停、继续、跳过目标、结束操作始终容易找到；结束和跳过说明真实影响。生成中的控制状态遵守当前后端并发语义。
- 面试过程优先让用户表达，不把对话气泡铺满整个屏幕；用面试官问题块和用户回答块维持轮次关系即可。

## 5. 面试交互状态设计

| 前端显示态 | 触发依据 | 主要反馈和动作 |
|---|---|---|
| 准备开始 | 已选择可用确认计划 | 显示计划摘要、模式；开始是一次可能等待的服务端操作 |
| 开场生成 | 创建请求进行中 | 显示正在准备首问；避免重复启动 |
| 等待回答 | 服务端有当前问题 | 焦点落到回答区；辅助材料可查看；保留当前轮次上下文 |
| 正在保存 | 已提交答案，尚无 ack | 锁定重复提交并保留输入；不能先显示“已保存” |
| 已保存，生成中 | 收到 ack，正在等决策/流增量 | 明确回答已进入记录；逐段显示新问题；流断开可恢复 |
| 流中断、状态待确认 | 客户端断开或错误，状态不确定 | 读取场次快照/事件；不盲目重发收费请求，不丢输入 |
| 下一步失败 | 已保存回答但决策失败 | 保留轮次，提供“重试下一步”；不要求重新回答 |
| 暂停 | 后端返回 paused | 保持记录可看，提供继续；提醒迟到决策不会继续写入 |
| 已结束、无报告 | 后端 completed，报告未生成 | 可回看全部问答；用户主动生成复盘 |
| 报告生成中/失败/就绪 | 报告接口状态 | 只呈现真实状态；失败保留记录并可显式重试 |

不能只用一个全局 `busy` 控制所有按钮。至少区分开始、回答保存、决策流、控制动作、参考资料读取、报告生成；每种状态与服务端快照共同决定可用动作。

## 6. 为后续语音预留的产品结构

文字闭环先做扎实，前端架构预留通道边界但不提前构造可点击的语音 UI：

```text
Interview Session (plan, objectives, turns, pause/resume/end, report)
  ├─ Text channel: answer editor -> saved text -> existing SSE next-turn flow
  └─ Voice channel (future): permission -> capture -> transcript draft/review
                      -> answer commit -> interviewer audio/playback -> interrupt/recover
```

未来必须明确设计这些状态：麦克风未授权/拒绝、录音中/暂停、静音与轮次结束判断、部分与低置信转写、用户修订、转写提交、AI 等待、播报中、用户打断、音频断线、恢复或降级为文字。口述内容在用户确认前是草稿，不能直接当成已保存答案；低置信转写不能作为能力不足证据。

语音场次是否与文字场次共享 `mode`、是否增加 channel 字段、实时传输采用 WebSocket/WebRTC 或模型供应商接口，须以后端契约设计确定。前端不自行定义协议，也不假设音频可以塞入当前 JSON answer SSE 接口。

## 7. 视觉语言方向

旧 Warm Editorial 色板与原生设计展示已作废。新视觉应以“专注练习与可信资料”作为品牌性格，既有辨识度，也不过度装饰。首轮概念建议：**训练工作室 / Studio**——界面像为个人准备的一间安静工作室，字体和留白建立专注感，结构线索与少量高对比强调色帮助定位；避免 AI 紫色渐变、大片数据卡、霓虹声波和聊天机器人模板。

用户反馈计划页与练习页风格割裂后，本轮以现有「练习场」页面为统一基准：四页共用 `App.vue` 的品牌、四项导航和当前页标识；`styles.css` 管理全局色彩、字体与外框变量，`workspace.css` 管理工作区标题、侧栏、按钮和反馈。移除三页独立的 FIELDNOTE 页头和大标题展示区；各页样式限定在自己的页面内，避免同名样式互相覆盖。页面可按任务采用不同内容布局，但不得再定义另一套品牌或导航。

实际中文长答案、代码、项目来源和计划摘要的密度与窄屏表现仍需用户体验后调整。此次未运行构建或浏览器验证。优先保证键盘可用、焦点可见、状态有文字、动效尊重 reduced-motion、窄屏作答不中断。

## 8. 当前实现入口与后续工作

- 本地开发：先启动 FastAPI，再在 `frontend/` 运行 Vite，访问 `http://127.0.0.1:5173/`。`/frontend-assets/` 是构建产物的资源前缀，不是开发入口。
- 构建使用：`frontend/dist/` 存在时，FastAPI 从 `http://127.0.0.1:8000/app/` 提供 Vue 应用，并将旧页面路径重定向到对应新版工作区。
- 四个工作区均已接入真实 API；视觉细节和响应式表现以用户体验反馈继续迭代。
- 旧原生资源暂作未构建时回退；待用户验收后再决定删除范围。
- 语音作为后续单独产品与协议设计，不与文字前端迁移捆绑。
