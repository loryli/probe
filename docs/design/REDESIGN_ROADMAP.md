# 练习场：UI/UX 重设计路线图

日期：2026-11-10。这是后续实施建议，不代表本阶段已获准修改业务、接口或数据结构。关联：[产品定位](PRODUCT_CONTEXT.md)、[现状审计](PROJECT_AUDIT.md)、[业务保护规则](BUSINESS_GUARDRAILS.md)。

## 1. 范围与实施方式

保留 FastAPI 同源多页应用、原生 HTML/CSS、ES Modules、Fetch 和数据库持久化。重设计围绕四个真实工作区推进，每次只交付一个可体验的范围。先做信息架构与状态设计，再迁移样式和呈现，最后根据使用反馈整理重复代码。

本阶段只产出这四份文档；不创建原型页面、不修改资源引用、不删除 CSS/JS、不运行服务、测试、模型或浏览器验证。后续默认由用户启动服务验收，只有用户明确要求才由 Agent 执行相应验证。

## 2. 阶段与交付

| 阶段 | 工作与交付 | 退出条件 | 依赖 |
|---|---|---|---|
| 0：准备（本轮） | 产品定位、源码审计、路线图、业务保护规则 | 四份文档区分事实、建议、冲突和未知 | 当前代码只读检查 |
| 1：体验规格 | 四页信息层级与低保真布局；阅读/编辑/生成/失败等状态矩阵；token、字阶、间距、滚动责任；DOM ID/事件依赖表 | 用户能评估每页主要任务、入口及恢复方式；未确认业务不被写进新流程 | 本轮文档 |
| 2：视觉基础与题库切片 | 统一 token/公共控件责任，先迁移题库；保留分类、搜索、批量移动、导入、历史与原文阅读 | 题目长答案可读，编辑入口清楚，分类操作高效；其余页现有功能保留 | 阶段 1 |
| 3：简历与项目 | 优化原件、文字、项目、草稿、历史的关系；已有只读/编辑与引用核对布局 | 能明确判断“预览/未保存/已保存/已核对”；未保存草稿不因布局切换丢失 | 共用基础与资料状态规格 |
| 4：面试计划 | 将配置、结果、确认、历史分层；清楚展示比例、覆盖率、依据与待确认提示 | 调整配置与重新生成含义清楚；旧结果不能冒充新结果；明细可达 | 阶段 1；当前 Planner 契约 |
| 5：模拟面试与回看 | 专注问题/回答布局、辅助面板与移动端策略；等待、保存、生成失败及报告状态 | 当前问题和输入为主；控制易找；收起辅助不丢光标；断线/错误状态可理解 | 面试状态和流式语义规格 |
| 6：跨页收尾 | 合并已证明一致的呈现工具、修正文案与导航；清理 CSS 责任和版本管理，更新交接 | 四页一致但布局各自适用；无隐藏功能、重复操作和残留覆盖 | 各切片由用户验收 |

语音界面另立后续任务。此路线图不提前实现录音、ASR、TTS、音频权限或新后台任务。

## 3. 下一阶段优先交付：体验规格

### 四种布局分别设计

- **题库**：保留“分类 → 题目 → 完整内容”的信息关系。桌面评估三栏宽度；中屏让分类收敛为横向或可收起入口；小屏以列表/详情切换或纵向布局做候选方案，不直接承诺新导航行为。全文阅读不以大面积只读表单替代，编辑明确可见。
- **资料**：资料导航与核对工作区。项目事实的内容、依据和核对状态相邻；上传预览与历史版本清楚分开。PDF 原件入口保留，不在本轮承诺内嵌 PDF 阅读器。
- **计划**：配置与结果各自有清楚的主动作。已有计划先读，调整配置进入显式状态；摘要和预算先展示，技术追踪信息、引用与模型自评按需展开。不能隐藏会影响确认的失效提示。
- **面试**：当前问题、回答草稿、保存/生成状态和必要控制为主；记录/目标/资料/详情按需查看。辅助面板采用推开还是覆盖需结合小屏、焦点与草稿体验决定，不能只统一成其它页面的两栏容器。

### 状态规格至少覆盖

| 通用状态 | 特殊状态 |
|---|---|
| 首次加载、空列表、空筛选、列表失败、部分刷新失败 | 导入预览、锁定选择、已确认批次 |
| 只读、新建、编辑、有改动、保存中、保存成功、取消 | OCR 等待/部分失败/重识别待保存、AI 候选载入/已确认 |
| 404、409、422、503、请求超时、结果未知 | Planner 运行中/失败/ready/confirmed/旧契约/配置漂移 |
| 正常/悬停/焦点/禁用，键盘和触屏入口 | 面试 active/paused/completed、回答未保存/已 ack、生成中/流中断/需重试、报告未生成/生成中/失败/就绪 |

每个主动作写明：作用对象、触发接口、是否写入、是否可能调用模型、何时显示成功、失败保留什么、用户下一步是什么。真实状态由服务端确定，视觉状态不得代替业务完成状态。

## 4. CSS 与模块迁移建议

目标责任划分为：基础与 token、公共控件、页面布局及页面状态。可以在现有文件中逐步收敛，不要求新建一整套目录。

1. 先登记 `styles/theme/页面/workspace` 中重叠选择器及断点；每次明确某组规则由哪个文件负责。
2. 保留现有资源文件，按页面迁移旧规则责任。以后确需删除或改动共享规则时，列出所有调用页面和回退方式，不在尚未迁移的页面上造成无意变化。
3. 不继续靠更长的 `body.page ...` 选择器覆盖上一层；公共样式不决定所有页面的栏数、高度和滚动方式。
4. 设计 token 变更只影响视觉语义；状态颜色与文本同时保留。`hidden`、焦点和 reduced-motion 支持不得被当作冗余去掉。
5. 优先复用 `renderRecord` 和两个现有控制器。请求/通知/分页确需抽取时，保留原有限时、binary、204、错误码和草稿行为；流式传输独立处理。
6. 原生 dialog 可服务确认和导入；非模态辅助面板单独定义关闭、焦点、遮挡和键盘行为，不强迫所有浮层使用同一实现。
7. 每批资源更新采用一致版本策略，包括入口导入的子模块；不以硬刷新作为长期发布策略。

## 5. 人工体验与交付要求

以下是供用户在后续实现阶段验收的场景，本轮没有执行：

- 桌面宽屏、笔记本低屏高、中屏、窄屏；建议参考 1440/1024/768/390px 以及 200% 缩放，不将这些数值当唯一设备标准。
- 长题干、含 Markdown/代码的长答案、空答案、长项目事实、多个候选和旧计划。材料必须来自用户授权的资料，不向实际数据库注入演示内容。
- 键盘浏览、可见焦点、Ctrl/Cmd+Enter、Tab 标签切换、dialog/抽屉关闭返回、减少动效；读屏和对比度另作明确验收，不宣称源码存在 ARIA 即已通过。
- 保存前离开、并发修改、上传失败、模型失败、连接中断、回答已保存但下一步失败；确保恢复入口可见且不会误发新调用。
- 每次交付说明页面入口、改动范围、保留的业务路径、用户体验步骤及未验证事项；不把“写完”报告为“已测试通过”。

## 6. 需要先澄清、可以暂缓的事项

**涉及业务，不能自行改变**：五分钟宽限自动收尾与软时长约定冲突；是否要改变参考答案查看规则；生成期间控制按钮的可用策略。可继续做其它布局设计，但相关状态按现状保留并注明待确认。

**可在设计阶段选定**：各页内容宽度、字阶、行高、断点、辅助抽屉宽度、长代码的阅读方式、英文 eyebrow 是否继续保留。选择应由真实内容和可操作性支撑。

**暂缓**：前端框架迁移、可视化组件平台、全局状态库、语音 UI、复杂画像、多用户、后台服务扩容。这些不构成本次视觉重构前置条件。

## 7. 后续 Agent 的任务边界

下一轮优先只做阶段 1。先阅读四份准备文档及当前 AGENTS.md，核对工作区变化；输出四页布局方案、状态矩阵和样式责任清单。实施阶段每轮指定一个页面或一组明确公共控件；保留数据库、接口、现有 CSS/JS 和未提交改动。需求不明确时记录问题，不能通过删除按钮、改调用时机或自动生成内容消除复杂度。
