# 练习场 UX Architecture

日期：2026-11-10。状态：**待用户确认的交互设计**，没有页面代码实现。

依据：[产品定位](PRODUCT_CONTEXT.md)、[项目审计](PROJECT_AUDIT.md)、[业务保护规则](BUSINESS_GUARDRAILS.md)。本次用户要求授权新增这六份设计文档，不沿用保护规则中上一阶段“仅创建四份文件”的任务数量限制；业务不变量继续有效。

## 1. 架构决策

练习场围绕“管理个人资料 → 选择训练目标 → 作答 → 回看”组织。四个工作区可以独立进入、反复往返，不设强制首次向导，不增加仪表盘首页。

| 工作区 | 主对象 | 默认模式 | 主布局 | 首要内容 |
|---|---|---|---|---|
| [个人题库](QUESTION_BANK_UX.md) | 用户问答 | 阅读 | 可收起分类 + 紧凑题目列表 + 宽阅读区 | 用户自己的答案 |
| [简历与项目](MATERIALS_UX.md) | 简历版本、项目、证据 | 已确认资料 | 资料导航 + 详情；核对时打开来源对照 | 已保存信息与来源关系 |
| [面试计划](PLANNER_UX.md) | 一次规划结果 | 计划记录 | 目录入口；创建使用分步全宽流程 | 资料范围、目标与预算 |
| [模拟面试](INTERVIEW_UX.md) | 当前问题和回答 | 专注 | 单主区；自由开关辅助面板 | 当前问题与回答编辑器 |

不复制其它产品的页面骨架。共享的层级是“位置 → 对象 → 任务 → 状态 → 辅助”，不是统一栏数或容器高度。

## 2. 全局信息架构

```mermaid
flowchart LR
    Q[个人题库：阅读与维护] --> P[面试计划：选择资料]
    M[简历与项目：核对事实] --> P
    P --> V[预览目标与预算]
    V --> C[确认计划]
    C --> S[面试开始页]
    S --> I[文字训练]
    I --> R[记录与复盘]
    R -. 用户主动进入 .-> Q
    R -. 用户主动进入 .-> M
    R -. 再次规划 .-> P
```

虚线不表示自动改资料、自动记忆或已有跨页写回接口。训练后只提供工作区入口，不自动创建练习题或新计划。

全局顶栏保留品牌与四个入口；正常工作区显示当前导航。面试房间进入专注壳：压缩导航为“退出工作区/导航”入口，保留场次标题与控制；切换工作区须保护未提交回答。全局健康状态降到非抢眼位置，失败影响当前操作时在任务旁展示具体原因。

## 3. 阅读、编辑、生成三种不同模式

| 模式 | 数据来源 | 主动作 | 离开语义 |
|---|---|---|---|
| 阅读 | 服务端已保存记录 | 编辑、查看来源/历史 | 不产生写入；保留同页列表上下文 |
| 编辑 | 内存草稿 + 已保存基线 | 保存、取消 | 有修改时确认放弃；不声称刷新后恢复 |
| 生成/审核 | 持久化任务、候选、人工草稿 | 读取结果、载入核对、确认 | 已持久化结果可回读，未保存编辑仍需保护 |

“已保存”只对应服务端成功。计划步骤完成不等于配置已存库；PDF 上传成功不等于简历已保存；AI 提取完成不等于项目已确认；面试流中出现文字不等于问题已正式落库。

跨页 URL/浏览器历史承载对象位置和前端视图上下文是后续前端建议，不改变现有后端资源路由。搜索、当前分页、列表滚动、选中对象在本次页面存活期间保留；跨刷新草稿和离开后返回恢复不作默认承诺。不得将私密正文放入 URL。

## 4. 空间与滚动系统

以下尺寸为设计起点，待真实内容体验后微调；不作为硬性设备判定。

| 宽度 | 题库 | 资料 | 计划 | 面试 |
|---|---|---|---|---|
| ≥1280px | 分类约180px、列表约300px；其余给正文 | 资料导航约240px，正文；来源对照只按需打开 | 创建区约960px，步骤侧栏约180px | 主区约760–880px；辅助约360px，仅够宽时并列 |
| 900–1279px | 分类收起，列表约280px，正文不少于约560px；空间不足转单详情 | 导航收起；来源/编辑切换，不硬塞三栏 | 顶部步骤，单主栏 | 主区保持可读，辅助为覆盖面板 |
| <900px | 列表与详情单视图，返回恢复列表位置 | 单详情/单审核候选，来源独立视图 | 单列步骤、底部上下步 | 单列作答，辅助为全屏面板 |

规则比断点更重要：阅读宽度不足时先收辅助栏，不把答案压成窄列。正文建议上限约880px；超宽屏余量用于导航和对照，不无限放大字行。必要阅读留白保留；空白不靠固定520px高卡片、巨幅欢迎插画或占位空栏制造。

**滚动归属**：主体文档拥有详情、编辑和步骤内容的纵向滚动；桌面题目/资料列表可在 sticky 侧栏内独立滚动。正文内部不再套一层固定高度滚动容器。代码块、PDF和浮层属于明确的局部滚动例外。移动端以单个页面或全屏面板滚动，不保留桌面多栏滚动。

头部只保留紧凑粘性定位和必要操作条，避免全局导航、标题、标签、保存栏同时占满低屏高。底部按钮区在支持时粘性显示并预留等高内容空间；软键盘弹起后不能遮挡输入、字段错误或提交按钮。流式更新不强制把正在阅读历史的用户滚回底部。

## 5. 通用反馈、空态与可访问性

- 每个视图一个明确主要动作，次要动作紧邻对象；删除属于低强调动作且确认影响范围。
- 初次空态在内容起点用短说明引导，不占整屏；主按钮留在固定位置。不把空筛选、读取失败和从未创建混为一谈。
- 请求失败保留筛选和草稿；字段错误紧邻字段；409 显示草稿保留及读取最新的选择，不自动覆盖。
- 生成等待展示真实阶段及等待时间，不显示虚构百分比。读取结果与重新付费调用分开。
- 状态用文字和颜色共同表达，统一“未保存/已保存/待核对/已核对/生成中/失败”等词，但不合并业务含义。
- 键盘焦点可见；Tab标签支持方向键与正确选中关系；原生表单保持语义。非模态并列面板允许回到回答编辑器；覆盖面板按模态管理焦点，Esc关闭后恢复选区/触发点。
- 流式文本不逐字触发整段读屏播报；保存、可作答、错误等里程碑单独通知。尊重 reduced-motion，不依赖动效理解状态。

## 6. 能力边界与待确认事项

| 分类 | 事项 | 设计处理 |
|---|---|---|
| 当前能力可重新组织 | 四页阅读编辑、分类导入、项目核对、分步收集配置、参考抽屉、复盘读取 | 以现有接口为依据；本阶段仅设计 |
| 新的前端呈现建议 | PDF 原件预览、步骤导航、从确认计划带入开始页、列表详情视图切换 | 不增加后端承诺；实施前确认前端传参与浏览器支持 |
| 缺少业务能力 | 可编辑个人信息/教育经历字段、自动知识点图谱、面试持久化自定义名称、语音录音 | 不设计假表单、自动AI建议或可点击假入口 |
| 产品规则待确认 | 超出计划五分钟自动收尾与不强制结束冲突 | 两者不合并；不新增倒计时或改结束条件 |
| 保持现状 | 查看参考答案是否影响评价、生成中暂停/结束限制 | 不新增扣分/考试模式，不擅自解除控制禁用 |

确认点为四页布局、分步计划、来源核对及专注面试的面板行为。用户确认设计后，另行进入页面实施；当前六份文档不代表运行验证或编码授权。
