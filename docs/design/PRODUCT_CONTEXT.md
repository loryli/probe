## 1. 决策依据

- **用户已确认**：个人面试训练工作台；四项核心任务；采用前后端分离的前端开发方式；开发时前端开发服务器单独运行并代理 FastAPI，生产构建产物由 FastAPI 同源托管，用户启动时仍只需运行一个服务。选型为 Vue 3 + TypeScript + Vite。
- **不再作为决策**：Warm Editorial 色彩方向、原生 HTML/CSS/ES Modules、拒绝 React/Vue，以及此前四页布局草案。它们来自效果不佳的旧设计，应在新体验规格中重新评估。
- **仓库事实**：当前已有题库、简历与项目、Planner、文字面试及整场复盘的页面与接口。逐轮后台分析、长期记忆和语音没有现成的完整产品流程。
- **设计建议**：本文中的字阶、空间组织、响应式策略和组件拆分需要在后续设计中细化，不代表已经实现或验收。
- **尚待确认**：见审计末尾的问题表。存在冲突时不得用视觉重构悄悄替代业务决策。

## 2. 产品服务谁、解决什么问题

首先服务用户本人，首发方向为大模型应用开发 / AI 全栈。用户已有自己的简历、项目经历及 Markdown 问答笔记，需要整理、练习、检验和复盘。

核心价值是把个人知识资产转化为有依据的训练：维护原题与自己的答案；整理真实项目事实；规划考察目标；在连续追问中验证理解；回看保存的回答和复盘。训练质量、资料可信度和日常操作效率，比装饰性的 AI 存在感更重要。

页面不是聊天首页或运营仪表盘：没有必要用对话气泡承载题库维护，也没有必要用大量统计卡片挤占答案阅读空间。

## 3. 四项任务与各自布局

| 工作区 | 用户的主要任务 | 建议组织方式 | 优先保护 |
|---|---|---|---|
| 个人题库 | 找到、阅读、整理和修改自己的问答 | 已有 Vue 页面；按实际体验继续调整 | 长答案、搜索筛选、分类移动、原文和历史 |
| 简历与项目 | 核对简历文字、项目事实与依据 | 已有 Vue 页面；按实际体验继续调整 | 来源与版本可追溯；人工核对后保存 |
| 面试计划 | 配置训练范围并理解生成结果 | 已有 Vue 页面；按实际体验继续调整 | 当前输入与已生成结果不混淆 |
| 模拟面试 | 理解当前问题、组织回答、推进训练 | 已有 Vue 页面；按实际体验继续调整 | 输入焦点、保存反馈、控制操作、失败恢复 |

统一的是导航、文字层级、颜色语义、控件行为与反馈语言；布局由任务决定。四个入口是可反复往返的工作区，不是每次都必须依次完成的向导。

## 4. 当前视觉方向与验收状态

| 角色 | 已确认颜色 | 使用原则 |
|---|---|---|
旧版色值仅为历史草案，不构成新方案约束。当前 Vue 页面按“专注练习与可信资料”的工作室方向实现；实际效果尚未由用户验收，需结合真实问答、简历、计划和面试内容继续修正色彩、字阶、密度、布局与组件语言。

保持内容可读、业务状态清楚的通用目标；具体美术细节由页面体验反馈确定。

## 5. 交互原则

1. **知识资产优先**：阅读用户原文是题库主体验，编辑是显式状态；不为了整洁而裁掉答案、代码或来源入口。
2. **动作结果明确**：保存内容、生成草稿、确认候选、读取结果、重新调用模型必须使用不同且稳定的名称。
3. **默认安静，信息可达**：面试辅助默认关闭；打开后保留回答草稿及光标。不能为减少按钮而把暂停、结束、恢复入口藏得难以找到。
4. **反馈跟随任务**：区分“保存中”“已保存、等待生成”“生成失败、回答仍在”；计时不冒充真实进度百分比。
5. **错误可恢复**：冲突保留草稿；连接失败不等于未保存；只读失败不诱发新的付费调用。
6. **键盘与触屏都可操作**：保留快捷键、可见焦点、原生表单语义、关闭与返回焦点路径。移动端布局不能只缩小桌面三栏。
7. **未来语音独立呈现**：未来可设计录音、转写和播报界面；本轮不预建语音按钮、假状态或新的会话流程。
