# 服务器部署与访问保护

状态为已提供配置，待用户在服务器验收。默认目标是单台 Linux/systemd 服务器，项目目录为 `/opt/probe`，适用于个人使用的 2 核 2 GB 服务器。其他系统需调整服务管理方式。

## 访问边界

浏览器通过域名 HTTPS 访问 Caddy，输入个人账号和密码后使用练习场。Caddy 认证覆盖所有路径，包括页面、API、原始 PDF、OpenAPI、健康检查和 SSE。FastAPI 仅监听本机 8000，使用一个 worker。前端使用构建产物，由 FastAPI 同源提供。

浏览器写请求受到 Origin 和 Fetch Metadata 限制。Apifox 可以使用 HTTPS 域名和 Basic Auth 调试，通常不需设置 Origin。网关不转发登录凭据给后端。应用和网关默认不记录逐请求访问日志，避免把文件名、URL 参数和认证信息写入访问日志。

HTTPS 由 Caddy 获取和续期证书。服务器需有可解析的域名，允许入站 TCP 80/443 及证书签发所需的出站访问。云安全组和主机防火墙仅开放网站 80/443 与管理员 SSH 端口，8000、5173 和 Caddy 管理端口 2019 保持关闭。保留当前 SSH 规则后再调整防火墙。

认证依赖本配置中的 Caddy 网关和回环监听。用其他命令把后端绑定到公网地址会绕过该保护。

## 准备应用

安装 Python 3.11+ 和 Caddy 2.8+，Caddy 使用官方的 `caddy.service`。安装方法见 [Caddy 官方安装说明](https://caddyserver.com/docs/install)。

将项目放到 `/opt/probe`。复制代码时排除本机 `.venv`、`node_modules`、`.env` 和个人 `data`。已有服务器数据应先备份，再独立迁移。生产更新期间保留服务器的 `.env`、`data` 和 `.cache`。

先在开发电脑构建前端，将 `frontend/dist` 一同上传，减少服务器的构建内存开销。

```powershell
cd E:\project\probe\frontend
npm ci
npm run build
```

以下是首次安装到专用服务器的 Bash 命令，后续更新跳过用户创建。代码目录由管理员管理，服务用户只需读取。

```bash
sudo useradd --system --user-group --home-dir /opt/probe/data --shell /usr/sbin/nologin probe
sudo install -d -o probe -g probe -m 700 /opt/probe/data /opt/probe/.cache
cd /opt/probe
sudo python3 -m venv .venv
sudo .venv/bin/python -m pip install -c constraints.txt -e .
sudo install -o root -g probe -m 640 .env.example .env
sudoedit /opt/probe/.env
```

在服务器的 `.env` 设置下列值，并填写原有 Qwen 配置。

```dotenv
INTERVIEW_ENVIRONMENT=production
INTERVIEW_DATABASE_URL=sqlite+aiosqlite:////opt/probe/data/interview.sqlite3
INTERVIEW_DATA_DIR=/opt/probe/data
INTERVIEW_OCR_MODEL_DIR=/opt/probe/data/ocr-models
```

production 环境必须显式提供数据库连接串，并手动迁移。使用 MySQL 时改为自己的连接串。初次安装或升级迁移时先停止已有服务，备份数据库和原始资料，再以服务用户执行。

```bash
cd /opt/probe
sudo -u probe .venv/bin/python -m alembic upgrade head
sudo install -m 644 deploy/probe.service /etc/systemd/system/probe.service
sudo systemctl daemon-reload
sudo systemctl enable --now probe
```

小内存服务器的 OCR 会额外占用内存，可先在电脑上完成 OCR 再上传核对后的资料。首次 OCR 模型下载需要出站网络与可写的数据目录。

## 配置网关

交互生成密码哈希，避免将明文密码写入命令行和历史记录。

```bash
caddy hash-password
sudo install -d -m 700 /etc/probe
sudo install -m 600 /opt/probe/deploy/gateway.env.example /etc/probe/gateway.env
sudoedit /etc/probe/gateway.env
```

填写真实域名、用户名和完整的 bcrypt 哈希。systemd 环境文件中的美元符号按字面保存，无需转义。不要通过 shell `source` 加载该文件。配置和哈希保存在仓库之外。

以下命令适用于专供练习场使用的 Caddy。若服务器已有网站，将练习场站点块合入现有 Caddyfile，保留其他站点与配置。

```bash
sudo install -m 644 /opt/probe/deploy/Caddyfile /etc/caddy/Caddyfile
sudo install -d -m 755 /etc/systemd/system/caddy.service.d
sudo install -m 644 /opt/probe/deploy/caddy-probe.conf /etc/systemd/system/caddy.service.d/probe.conf
sudo systemctl daemon-reload
sudo systemctl restart caddy
```

服务启动时会读取网关环境文件并加载配置，配置无效时不会切换到无认证代理。密码或域名变更后执行 `sudo systemctl restart caddy`，让 systemd 重新读取环境文件。浏览器可能缓存旧凭据，更换后重新输入，或使用新隐私窗口访问。Basic Auth 使用浏览器原生提示，没有应用内退出登录按钮。

打开 `https://你的域名/app/`，登录后使用手机录音。模型调用仍遵循页面明确触发的行为。

## 用户验收

本次交付未执行安装、构建、迁移、服务器启动或浏览器验证。部署后检查以下项目。

- 隐私窗口访问首页、`/openapi.json`、PDF 原件链接和 SSE 接口均要求认证。无凭据请求应为 401，不返回个人数据。
- 使用错误密码仍返回 401。正确密码能访问题库、资料、计划和面试。
- 外部访问服务器 8000/5173/2019 端口失败。服务器本机可连接 `127.0.0.1:8000`。
- 在手机 HTTPS 页面允许麦克风，完成录音、转写、核对与提交。
- SSE 及时返回已保存状态。断线后重新读取场次，重复点击不产生额外模型任务。
- 带合法认证但 Origin 为其他网站的写请求返回 403。

可以在自己电脑的终端用以下命令检查。先替换域名和用户名，`--user owner` 会交互提示密码，密码不出现在命令行。第一条预期 401，第二条预期 200，第三条预期 403。跨站检查使用健康路径，即使网关配置错误，也不会创建面试或调用模型。

```bash
curl -i https://practice.example.com/health/live
curl -i --user owner https://practice.example.com/health/live
curl -i --user owner -X POST -H "Origin: https://other.example" https://practice.example.com/health/live
```

在服务器执行 `ss -lnt` 查看监听地址，8000 应仅为 `127.0.0.1:8000`。网站启用了 HSTS，浏览器首次成功通过 HTTPS 访问后会优先使用 HTTPS。

查看服务状态和错误日志的命令如下，向他人分享日志前去掉个人资料与敏感信息。

```bash
sudo systemctl status probe caddy
sudo journalctl -u probe -u caddy -n 80 --no-pager
```

配置依据为 [Caddy Basic Auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth)、[反向代理与流式响应](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)和 [systemd 服务配置](https://caddyserver.com/docs/running#using-the-service)。
