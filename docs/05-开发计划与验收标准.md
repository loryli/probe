# 开发阶段与验收标准

## 1. 实施策略

先确定数据边界和可用交互方式，再做一条从配置到面试到复盘的垂直切片。逻辑模块先作为同一应用内模块实现；只有出现可测量的扩展/运行需求后才拆分服务或引入复杂编排。

以下阶段不绑定日历工期；每一阶段完成后，以可操作的产品能力作为验收，而不是以模块数量验收。

## 2. 阶段计划

### 阶段 0：最小技术验证

**工作**：首发岗位已定为大模型应用开发 / AI 全栈，交互已定为先文字；验证 Python + FastAPI + Pydantic、MySQL、SSE 和一个云端模型的最小链路。前端与任务队列按最小实现选型。

**产物**：可调用模型并通过 Pydantic 校验结构化输出的 FastAPI 原型；MySQL 持久化一条面试状态；SSE 推送一次响应；前端技术选择记录。

**退出条件**：端到端模型调用和状态保存可用；云端模型接入配置完成；前端选择明确。语音和向量数据库不作为 V1 阻塞项。

### 阶段 1：用户资料与题库

**工作**：个人工作区、简历上传/文本输入、离线解析和人工校正；题库 CRUD/导入；元数据分类；原文与 AI 元数据隔离。

**建议垂直切片**：导入一份简历 → 校正一个项目事实 → 导入一道通用题 → 运行元数据分类 → 验证题干/答案内容哈希未变。

**退出条件**：解析失败可恢复；用户能修改事实；元数据重跑不改变原文；导入错误可定位。

### 阶段 2：文本模拟面试闭环

**工作**：Planner 输入配置并预览目标/预算；状态机；项目问题提供器、题库抽题器；统一 Fast Path Agent； turn 记录；暂停/跳过/结束。

**退出条件**：一次完整面试能够跨越项目题与通用题；追问根据回答变化；Agent 不受固定问题列表驱动；预算和用户控制生效。

### 阶段 3：三级分析与结构化复盘

**工作**：Background 任务和重试；Offline 汇总；逐题证据引用；记忆证据表；复盘界面。

**退出条件**：异步分析延迟/失败不影响实时对话；离线分析可以重试；每条重要结论链接到回答证据；删除场次按规则清理派生数据。

### 阶段 4：语音与使用体验完善（后续阶段）

**工作**：在文字闭环稳定后，语音输入/转写/播报或实时语音适配；打断和静音处理；低置信转写澄清；断线恢复；重点测量端到端延迟和成本。

**退出条件**：语音链路能识别轮次结束且保留可校正转写；转写不确定时不误判知识；断线后能恢复场次。

### 阶段 5：记忆迭代

**工作**：重复证据聚合、趋势和时间衰减、可解释能力主题视图；按真实复盘反馈调整置信度策略。

**退出条件**：长期结论可追溯、可修正；不会由单轮表现生成确定画像；用户能发现历史变化对下一次 Planner 的实际价值。

## 3. 验收标准

### 产品/业务验收

- [ ] 用户能在面试前维护/校正简历项目，并查看来源证据。
- [ ] 用户能维护问题和标准答案；AI 元数据可审核，原文保持不变。
- [ ] Planner 根据用户配置生成目标、时间预算、题源比例和约束，不产生固定问题清单。
- [ ] 项目问题能引用简历事实；通用问题来自启用题库；没有材料时系统说明并降级。
- [ ] 不上传简历也可选择题库、生成确认计划并完成文字练习，所有问题均来自冻结的题库原题，没有 AI 自拟追问。
- [ ] 上传并核对简历后，AI 直接填入名称、技术栈、简介和多条描述的项目表单；逐个确认才保存，来源依据可按需展开。助手未代替用户运行验收。
- [ ] 一个 Interview Agent 能连续处理两类题及动态追问。
- [ ] 用户可暂停、继续、跳过和结束，控制动作不会被 AI 决策覆盖。
- [ ] 结束后可查看逐题和整体复盘，观察有 turn 证据引用。
- [ ] V1 记忆表现为结构化证据记录；不声称有完整或永久准确的能力画像。

### 正确性与可靠性验收

- [ ] Planner 输出通过结构校验；时间预算合计有效，目标引用可用材料。
- [ ] Fast Path 输出不合法/超时有确定性回退，并能继续或安全结束面试。
- [ ] 后台任务幂等、可重试；同一输入版本重试不重复生成观察。
- [ ] 简历解析/题库导入/模型服务失败时，已保存原始材料不丢失。
- [ ] 用户原题、答案的更新路径与 AI 元数据更新路径物理分离，并有回归验证。
- [ ] 断线恢复后 session/turn 顺序一致，无重复提问或丢失已保存回答。
- [ ] 删除操作覆盖关联文件与派生分析/记忆，具体实现符合最终数据保留决策。

### 体验验收

- [ ] 追问一次只问一个问题，语气自然，避免重复刚刚已回答的内容。
- [ ] 时间不足时不突然截断回答；说明进入收尾并优先完成高优先级目标。
- [ ] 低置信转写先确认内容，不把识别错误作为能力缺陷。
- [ ] 项目追问引用材料中有根据的内容，不将模型推断说成用户做过的事实。
- [ ] 复盘建议具体且少量；区分答案覆盖、技术正确性、表达质量和未核实主张。

## 4. V1 发布门槛

V1 的首发门槛是「可连续使用的可靠闭环」，而不是所有未来能力：

1. 一份用户简历和一份个人题库可被管理与校正。
2. 用户可以预览 Planner 计划，并完成一场项目题 + 通用题模拟。
3. 实时决策链路具备超时回退，异步分析不阻塞对话。
4. 面试记录可回看，复盘有证据链接，删除策略清楚。
5. 模型服务可通过适配器替换，不把供应商字段泄漏进核心领域实体；语音留待后续阶段。

## 5. 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| Fast Path 延迟破坏面试节奏 | 先短上下文、短 schema、严格超时；准备程序化安全回退；确认模型后实测再定目标。 |
| AI 编造项目细节 | 项目题需引用 fact ID；Agent 只对已确认事实提问；输出问题时校验引用。 |
| AI 误改用户答案 | 题库元数据单独实体与写 API；原文内容哈希/版本用于校验。 |
| Planner 计划僵化 | 只锁目标与预算；目标内局部自主；重要偏离记原因。 |
| 单次回答导致错误能力画像 | V1 只保存证据观察；长期趋势基于多次证据并保持可追溯。 |
| 语音范围膨胀 | 领域会话接口先支持文本；语音作为适配器并独立验收。 |
| 前端与后台任务演进 | 文字闭环已有可用页面；前端已确认独立开发并由 FastAPI 同源托管构建产物。后台队列仍按实际重试和跨重启需求决定。前端开发约定见 `docs/frontend/README.md`。 |

## 6. 设计审查待办

记录于 2026-11-23，依据提交 `fd9550e` 的源码。下列现状来自代码审查，改进方向和验收项供后续实施。

### 6.1 保护暂停和恢复时的语音草稿

**实施状态（2026-11-23）**：已修改，待用户验收。暂停保留组件和同题候选，录音中暂停会停止采集并暂存待上传录音，恢复后可明确上传。临时禁用作答不会清空草稿。离开、跳题、结束及有语音草稿时仅提交文字均有确认提醒。本页录音仍在内存中，刷新后的恢复范围为服务端已接受的转写任务。

**现状**：语音组件在作答入口禁用时重置。暂停请求一发出就会暂时禁用作答，即使暂停失败也可能清除录音、转写候选和恢复任务所需的标识。切换场次或离开时，现有丢弃确认只看文字草稿。[语音组件](../frontend/src/components/VoiceAnswer.vue) · [面试状态](../frontend/src/composables/useInterview.ts)

**改进与验收**：按场次和问题管理录音、转写任务与候选，将暂时禁用操作和丢弃草稿分开。暂停时停止采集，保留同题已录内容。暂停成功、失败或恢复后，均能继续核对本题草稿。结束、切题或离开时提醒用户处理未提交内容，晚到转写不得覆盖其他题的回答。

### 6.2 在调用模型前锁定复盘任务

**实施状态（2026-11-23）**：已修改，待用户验收。迁移 `0015_interview_execution` 增加按场次和操作唯一的执行租约。复盘调用前认领，重复请求提示正在生成或返回已有成品，结果写入核对租约所有者与有效期，成品不被失败结果覆盖。运行状态保存于租约表，报告接口的既有结果结构保留。

**现状**：整场复盘完成模型调用后才写入报告。并发请求在报告尚未生成时可能各自调用模型，较晚失败的请求还可能清空已成功的报告。[复盘服务](../src/interview_assistant/interview/reporting.py)

**改进与验收**：调用前持久化运行状态并原子认领，完成回写核对任务尝试标识。并发点击、同一请求重放或超时后重新查询均复用原任务。过期任务可按状态恢复，旧请求的失败结果不得覆盖成品。

### 6.3 统一实时决策与重试的执行保护

**实施状态（2026-11-23）**：已修改，待用户验收。流式、后台与重试决策共用数据库执行租约，下一题生成也单独认领。重复进入时读取场次状态，运行中的 SSE 缓存延长保留。执行有总超时，结束释放租约，进程异常退出后租约到期可显式重试。事务内核对执行权，失效任务不能继续落库。供应商已经接收的请求在进程崩溃或断网后仍可能产生费用，本地执行锁无法撤销该请求，恢复后不自动重发收费调用。

**现状**：流式入口有进程内任务保护，但手动重试直接进入决策。并发重试或流式生成与重试重叠时，最终状态校验能限制迟到写入，仍可能发出重复的付费请求。[面试服务](../src/interview_assistant/interview/service.py) · [流式任务管理](../src/interview_assistant/interview/streaming.py)

**改进与验收**：流式入口和手动重试共用按场次与待处理回答认领的任务，记录执行期限和尝试标识。同一回答同时只允许一个调用在运行。断线重连读取已有结果或订阅任务，旧调用不得推进已暂停、已结束或已切换问题的场次。

### 6.4 支持用原录音重试，并明确草稿保留期

**实施状态（2026-11-23）**：已接入本页原录音重试，待用户验收。任务失败或过期时可确认发起新转写，上传结果未知时先读取原任务。转写成功、丢弃或离开页面后释放音频。服务端草稿仍按 30 分钟限制读取，并按访问和后续任务清理正文。

**现状**：服务端接收任务后，前端会释放待上传音频。转写失败后只能重录或改用文字。30 分钟是转写草稿的可读取期限，数据库中的过期正文只在读取对应任务或后续执行转写时清理，没有定时清理。[语音组件](../frontend/src/components/VoiceAnswer.vue) · [转写服务](../src/interview_assistant/interview/transcription.py)

**改进与验收**：本页暂存录音，用户可在转写失败后选择用同一录音重新转写。上传结果未知时先查原任务，确认失败后的新调用由用户明确触发。成功、明确丢弃或离开后释放本页音频。若需要承诺过期后主动清除数据库正文，补充清理机制，并验证没有后续转写时也能清除过期正文。

### 6.5 外网部署前保护全部访问入口

**实施状态（2026-11-23）**：已提供 Caddy HTTPS、全路径 Basic Auth、跨站写请求拦截和 systemd 单 worker 回环监听配置，待服务器部署验收。配置文件位于 `deploy/`，使用步骤见[服务器部署与访问保护](./07-服务器部署与访问保护.md)。实际生效依赖服务器按文档安装网关、填写凭据并限制端口。

**现状**：应用没有统一的身份校验。若将服务直接暴露到外网，未授权访问者可能读取或修改个人资料、调用付费模型。SSE 任务和事件缓存在进程内。[应用入口](../src/interview_assistant/main.py) · [流式任务管理](../src/interview_assistant/interview/streaming.py)

**改进与验收**：单用户外网部署可在网关统一配置 HTTPS 和访问验证，覆盖页面、API、SSE 和 PDF 原件，后端只允许网关或本机访问。先使用单个 FastAPI worker，并在手机端验收登录、录音和 SSE 断线恢复。

### 6.6 展示 Planner 使用了哪些记忆证据

**实施状态（2026-11-23）**：已接入计划生成前的证据选择与结果快照展示，待用户验收。简历模式的模型计划可选择最近 30 条已确认记忆，支持全部排除。选中条目失效时阻止生成并提示刷新。规则计划和纯题库练习不采用记忆。旧计划的快照照常读取。

**现状**：Planner 取最近 30 条已确认记忆并随计划冻结。选择未按本次目标或项目筛选，页面也未展示哪些证据进入计划输入。[计划服务](../src/interview_assistant/planner/service.py) · [计划页面](../frontend/src/views/PlannerView.vue)

**改进与验收**：先展示纳入的证据、来源和用途，允许用户在生成前排除与本次练习无关的条目。仅使用已确认且未排除的证据，后续记忆变动不得改写已确认计划。积累使用反馈后再决定是否增加按主题或项目筛选。

### 6.7 让较早的场次可回看

**实施状态（2026-11-23）**：记录管理支持分页、打开任意页场次和本页批量删除，待用户验收。删除后若当前页已空，回退至有效页。从旧场次可查看复盘、确认或忽略记忆。

**现状**：场次列表接口支持分页，但前端固定读取前 20 条。较早的场次仍可保存在数据库中，用户却难以从列表找到复盘和待确认记忆。[前端场次接口](../frontend/src/api/interviews.ts) · [后端场次接口](../src/interview_assistant/interview/router.py)

**改进与验收**：复用现有分页参数实现翻页或加载更多。超过 20 场后，仍能从列表打开旧场次、查看报告和处理记忆候选。

建议顺序为语音草稿保护 → 复盘与实时决策的重复调用保护 → 原录音重试与保留期 → 历史与记忆管理。访问保护是外网部署的前置条件。现有录音链路稳定后，再评估实时转写。
