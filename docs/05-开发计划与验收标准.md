# 开发阶段与验收标准

## 1. 实施策略

先确定数据边界和可用交互方式，再做一条从配置到面试到复盘的垂直切片。逻辑模块先作为同一应用内模块实现；只有出现可测量的扩展/运行需求后才拆分服务或引入复杂编排。

以下阶段不绑定日历工期；每一阶段完成后，以可操作的产品能力作为验收，而不是以模块数量验收。

## 2. 阶段计划

### 阶段 0：最小技术验证

**工作**：首发岗位已定为大模型应用开发 / AI 全栈，交互已定为先文字；验证 Python + FastAPI + Pydantic、MySQL、SSE 和一个云端模型的最小链路。前端与任务队列按最小实现选型。

**产物**：可调用模型并通过 Pydantic 校验结构化输出的 FastAPI 原型；MySQL 持久化一条面试状态；SSE 推送一次响应；前端技术选择记录。

**退出条件**：端到端模型调用和状态保存可用；云端模型接入配置完成；前端选择明确。语音和向量数据库不作为 V1 阻塞项。

### 阶段 1：用户资料与题库

**工作**：个人工作区、简历上传/文本输入、离线解析和人工校正；题库 CRUD/导入；元数据分类；原文与 AI 元数据隔离。

**建议垂直切片**：导入一份简历 → 校正一个项目事实 → 导入一道通用题 → 运行元数据分类 → 验证题干/答案内容哈希未变。

**退出条件**：解析失败可恢复；用户能修改事实；元数据重跑不改变原文；导入错误可定位。

### 阶段 2：文本模拟面试闭环

**工作**：Planner 输入配置并预览目标/预算；状态机；项目问题提供器、题库抽题器；统一 Fast Path Agent； turn 记录；暂停/跳过/结束。

**退出条件**：一次完整面试能够跨越项目题与通用题；追问根据回答变化；Agent 不受固定问题列表驱动；预算和用户控制生效。

### 阶段 3：三级分析与结构化复盘

**工作**：Background 任务和重试；Offline 汇总；逐题证据引用；记忆证据表；复盘界面。

**退出条件**：异步分析延迟/失败不影响实时对话；离线分析可以重试；每条重要结论链接到回答证据；删除场次按规则清理派生数据。

### 阶段 4：语音与使用体验完善（后续阶段）

**工作**：在文字闭环稳定后，语音输入/转写/播报或实时语音适配；打断和静音处理；低置信转写澄清；断线恢复；重点测量端到端延迟和成本。

**退出条件**：语音链路能识别轮次结束且保留可校正转写；转写不确定时不误判知识；断线后能恢复场次。

### 阶段 5：记忆迭代

**工作**：重复证据聚合、趋势和时间衰减、可解释能力主题视图；按真实复盘反馈调整置信度策略。

**退出条件**：长期结论可追溯、可修正；不会由单轮表现生成确定画像；用户能发现历史变化对下一次 Planner 的实际价值。

## 3. 验收标准

### 产品/业务验收

- [ ] 用户能在面试前维护/校正简历项目，并查看来源证据。
- [ ] 用户能维护问题和标准答案；AI 元数据可审核，原文保持不变。
- [ ] Planner 根据用户配置生成目标、时间预算、题源比例和约束，不产生固定问题清单。
- [ ] 项目问题能引用简历事实；通用问题来自启用题库；没有材料时系统说明并降级。
- [ ] 一个 Interview Agent 能连续处理两类题及动态追问。
- [ ] 用户可暂停、继续、跳过和结束，控制动作不会被 AI 决策覆盖。
- [ ] 结束后可查看逐题和整体复盘，观察有 turn 证据引用。
- [ ] V1 记忆表现为结构化证据记录；不声称有完整或永久准确的能力画像。

### 正确性与可靠性验收

- [ ] Planner 输出通过结构校验；时间预算合计有效，目标引用可用材料。
- [ ] Fast Path 输出不合法/超时有确定性回退，并能继续或安全结束面试。
- [ ] 后台任务幂等、可重试；同一输入版本重试不重复生成观察。
- [ ] 简历解析/题库导入/模型服务失败时，已保存原始材料不丢失。
- [ ] 用户原题、答案的更新路径与 AI 元数据更新路径物理分离，并有回归验证。
- [ ] 断线恢复后 session/turn 顺序一致，无重复提问或丢失已保存回答。
- [ ] 删除操作覆盖关联文件与派生分析/记忆，具体实现符合最终数据保留决策。

### 体验验收

- [ ] 追问一次只问一个问题，语气自然，避免重复刚刚已回答的内容。
- [ ] 时间不足时不突然截断回答；说明进入收尾并优先完成高优先级目标。
- [ ] 低置信转写先确认内容，不把识别错误作为能力缺陷。
- [ ] 项目追问引用材料中有根据的内容，不将模型推断说成用户做过的事实。
- [ ] 复盘建议具体且少量；区分答案覆盖、技术正确性、表达质量和未核实主张。

## 4. V1 发布门槛

V1 的首发门槛是「可连续使用的可靠闭环」，而不是所有未来能力：

1. 一份用户简历和一份个人题库可被管理与校正。
2. 用户可以预览 Planner 计划，并完成一场项目题 + 通用题模拟。
3. 实时决策链路具备超时回退，异步分析不阻塞对话。
4. 面试记录可回看，复盘有证据链接，删除策略清楚。
5. 模型服务可通过适配器替换，不把供应商字段泄漏进核心领域实体；语音留待后续阶段。

## 5. 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| Fast Path 延迟破坏面试节奏 | 先短上下文、短 schema、严格超时；准备程序化安全回退；确认模型后实测再定目标。 |
| AI 编造项目细节 | 项目题需引用 fact ID；Agent 只对已确认事实提问；输出问题时校验引用。 |
| AI 误改用户答案 | 题库元数据单独实体与写 API；原文内容哈希/版本用于校验。 |
| Planner 计划僵化 | 只锁目标与预算；目标内局部自主；重要偏离记原因。 |
| 单次回答导致错误能力画像 | V1 只保存证据观察；长期趋势基于多次证据并保持可追溯。 |
| 语音范围膨胀 | 领域会话接口先支持文本；语音作为适配器并独立验收。 |
| 前端和后台队列仍待选择 | 先用最小 Web 界面和轻量后台执行方式完成闭环；只有真实使用需要时再增加队列基础设施。 |
