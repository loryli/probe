# 产品边界、假设与待确认项

## 已确认的产品方向

| 决策 | 当前约束 |
|---|---|
| 目标用户 | 首先服务本人；暂不按商业化多用户平台设计。 |
| 首发岗位 | 大模型应用开发、AI 全栈。岗位标签可配置，首发目标模板按该方向准备。 |
| 首发交互 | 第一版先做文字面试；语音后续再优化延迟并接入。 |
| 数据与模型 | 用户表示数据存储位置不限，允许云端模型处理；隐私不是当前方案约束。密钥管理与数据删除仍属于基本工程要求。 |
| 技术栈偏好 | 优先沿用简历体现的 Python、FastAPI、Pydantic、MySQL、SSE；前端技术未从简历确认。 |
| 核心价值 | 检验整理好的知识、围绕简历项目深挖、逐次积累面试证据。 |
| 简历 | 解析发生在面试前的离线阶段；面试时使用已解析的项目事实和技术线索。 |
| 项目题 | 根据简历项目和面试上下文动态生成，不需要预先维护固定题库。 |
| 通用题 | 用户维护问题与标准答案；AI 只生成/建议分类、标签、难度等元数据，不改写原文。 |
| Planner | 生成考察目标、项目题/通用题比例、目标优先级、时间预算与追问上限；不生成固定问题清单。 |
| 实时对话 | 一个统一 Interview Agent 接收两种问题来源，并依回答决定追问、切换主题或结束。 |
| 分析 | Fast Path 实时决策；Background Path 异步深度分析；Offline Path 面试后汇总和记忆更新。 |
| 自主程度 | Planner 约束整体方向与预算；Agent 可在目标范围内局部调整具体问题。 |
| 记忆 | V1 保存结构化记录和有证据的观察；后续再评估能力模型，不先做复杂知识图谱。 |
| 非目标 | V1 不做多用户/共享题库、自动答案生成、复杂多 Agent、复杂知识图谱。 |

## 设计假设（需要用户确认后再固化）

1. 采用个人工作区：一个私有工作区，不提供注册、团队共享或租户隔离。数据位置可按部署成本和使用便利选择；云端模型处理已获用户认可。
2. 第一版以文本输入/输出完成面试闭环。会话领域接口保持可接语音，后续再引入语音输入、转写、TTS 或实时音频模型，并单独评估延迟。
3. Planner 中的比例按「预计面试时间」分配，而非精确题目数量；动态追问会消耗当前来源的预算。短面试可用最小时间片避免比例失真。
4. 默认允许用户在开场前预览/调整 Planner 结果，避免一次错误解析支配整场模拟。
5. 用户维护的题目和答案原文采用版本化或不可变快照，AI 元数据单独保存并允许人工覆盖。
6. 复盘中的技术判断应附引用到回答文本/转写片段的证据；AI 推断与确定事实分开表达。
7. 面试过程中的历史记忆只提供少量相关摘要，不加载全部历史记录；V1 不在每轮同步重写长期画像。

## 待确认项

这些项目不会阻止先做产品与领域模型，但在选择服务、部署和语音实现前应确认。

| 项目 | 需要决定什么 | 对方案的影响 |
|---|---|---|
| 面试语言 | 中文、英文或按场次选择 | 语音识别、TTS、Prompt 与评估用语。 |
| 前端实现 | 选择熟悉的前端方案，或采用学习成本低的轻量界面 | UI 技术与联调方式；简历没有明确列出前端技术。 |
| 数据部署位置 | 云端/本地/混合可选；用户接受云端模型处理 | 具体托管与备份方案。数据位置无需成为产品阻塞项。 |
| 后台任务实现 | 轻量进程任务或 Redis 队列 | 根据部署形态和任务可靠性决定，避免首版过度配置。 |
| 模型和成本约束 | 可用模型、预算、离线能力、延迟目标 | Fast/Background/Offline 模型路由与超时策略。 |
| 简历格式 | PDF、DOCX、纯文本等首发范围 | 文档抽取器和解析失败处理。 |
| 语音延迟目标 | 计划何时接入、可接受的端到端延迟 | 后续语音适配器和模型选择。 |
| 数据备份/保留 | 会话、转写、音频保存多久；导出格式 | 隐私与存储实现。 |
| 主观评价尺度 | 是否需要分数、采用哪些维度、是否只显示证据和建议 | 复盘 UX 和评估契约。 |

## 不应在实现中默认化的内容

- 岗位默认聚焦大模型应用开发 / AI 全栈，同时保留按场次配置岗位和方向。
- 不把 AI 生成的答案保存为用户标准答案。
- 不要求逐字复述标准答案；评估覆盖的关键知识点、技术正确性和表达清晰度。
- 不让后台分析任务阻塞下一轮面试响应。
- 不因历史一次回答就认定长期能力高低；记忆记录需带证据、置信度和时间。
