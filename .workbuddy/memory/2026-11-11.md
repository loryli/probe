## 17:32 修复 AI 提取项目事实「卡住 + 假进度」（用户截图反馈）

- **现象**：顶部浮层与项目区同时显示「Qwen 正在阅读简历并提取项目事实…（已用 87 秒）」，配一条 CSS 无限循环进度条，下方仍显示「没有项目事实 / 添加第一个项目」。
- **根因**：`POST /materials/resumes/{id}/parse-drafts` 把 Qwen 调用**同步跑在 HTTP 请求内**（原 `parsing.py create` 第 156–183 行），前端挂 330 秒等结果；2 秒轮询读到的永远是 `running`，阶段文案被反复重设，进度条是纯装饰。刷新/断网会让请求中断且草稿停在 running。
- **后端**：`ResumeParser.create()` 拆为「只落 running 草稿 + 幂等重放」，返回 `(draft, created)`；新增 `ResumeParser.run()` 与模块级 `run_parse_draft()`（独立会话、异常写 failed）；`parse_router` 用 `BackgroundTasks` 在响应后提交任务，POST 立即返回，`created=false` 不重复发起收费调用。模型调用仍不持事务。
- **前端**：POST 超时 330s→20s；删掉 `startParseWatch` 的第二个轮询，`waitForParseDraft` 成为唯一轮询源并用 token 支持「停止等待」；删除 `parsingBanner`、假进度条与 `parse-sweep` 动画，改为「后台执行 + 每 2 秒读状态 + 无进度百分比 + 可停止等待」；运行中屏蔽「没有项目事实」空状态；候选为 0 时明确说明引用未逐字匹配并引导手动选取；离开页面文案改为结果保存在服务端、不重复调用模型。
