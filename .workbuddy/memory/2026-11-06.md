## 技术决策

- Planner 只输出考察目标与预算，不输出固定问题清单或具体问题文本；schema 用 `extra="forbid"` 阻断额外字段。
- 比例换算、时间预算分配、开场/收尾缓冲、追问上限钳制、目标编号、引用有效性校验**全部由服务端程序完成**，模型只输出语义目标。
- 计划固定引用所选简历版本，快照保存项目事实 ID、题目 ID 与题目 `content_version`；确认前复核，资料变化则要求重新生成。
- 复用 `ai/qwen.py` 适配器（单次调用、事务外、request_id 幂等、不自动重试）；额外提供显式「规则模式」本地生成，保证密钥未就绪时页面闭环仍可验证，并明确标注未调用模型。
- 不向模型发送简历全文、标准答案或复习笔记；独立 `interview_plan` 表，后续面试场次可引用 `plan_id`，本轮不建 session/turn 表。

## 本轮追加：Planner 质量与实时链路优化（17:12）

用户提供真实运行结果（45 分钟、qwen-plus、53.8 s、5598/2083 tokens、8 个目标），指出 Planner 决定后续提问水平并影响语音对答反应速度，要求先优化该模块。评价中确认的问题：模型提示出现「简历 v6」幻觉（所选 v2）、模型自由文本未标注来源、目标文本夹带具体技术细节但只挂 1–2 条引用、40 道题仅 4 道进入目标且不透明、追问预算贪心扣减导致尾部目标 0 追问、completion_rule 接近具体追问、53.8 s 无进度反馈、摘要列举未覆盖主题。

- 技术决策：**模型只输出语义骨架，数字/摘要/上下文/校验全部服务端化**。发给模型的题干压到 80 字、事实 120 字，输出主题 ≤80 字、证据 ≤3 条、完成规则 ≤120 字、目标数按时长程序化 4–8 个；用 `model_validator(mode="before")` 裁剪长度、数量与未知字段，避免模型格式偏差导致整份计划失败（此前 after validator 的截断在 max_length 校验前不生效）。
- 服务端新增：程序化摘要（弃用模型 session_summary）、追问配额「保底 1 次 + 按优先级分配剩余」、覆盖率统计、提示三分区（系统/模型未核验/产品规则）、`foreign_versions` 版本号幻觉剔除与目标文本扫描、按目标预编译 `runtime_context`。
- 新增 `GET /interview-plans/{id}/runtime`（仅 confirmed）精简投影，为后续 Fast Path / 语音链路提供零 join、零二次模型调用的上下文；`PlanOutput` 的 `notes`/`coverage`/`runtime_context` 均可选，优化前计划仍可读，页面把旧 limitations 兜底按模型自评展示。
- 前端：分区提示、每个目标展开引用事实原文/题干与运行时上下文、覆盖率卡片、生成等待计时、元信息 " · " 分隔。
- 提示词版本升至 `planner_prompt.v2` / `planner_rule.v2`；无新迁移、无新依赖。
- 遗留：本轮按约定未运行任何验证，延迟/token/目标质量的实际改善需用户重新生成计划对比；目标文本与引用事实之间仍只有 ID 有效性校验，没有语义支撑校验，依赖页面引用明细人工核对。
