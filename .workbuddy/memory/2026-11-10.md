# 2026-11-10

## 逐字流式 + 开场提速

用户反馈「还是很慢，而且体验没有流式」。上一轮的「保存即返回 + SSE 轮询快照」只解决了界面卡死，模型仍是一次性吐完，没有任何增量。

- **`ai/qwen.py`**：新增 `generate_stream()`，用 `client.stream` 逐帧解析 SSE 的 `delta.content`，边收边 yield；`self.result` 存校验后的对象，`self.first_token_ms` 记录首包时间。状态码映射抽成 `_raise_for_status()`，非流式调用同步复用。
- **契约 `interview_decision.v2`**：`DecisionDraft` 增加 `say`（面试官下一句），字段顺序改为 `objective_status → follow_up_needed → say → next_objective_id → follow_up_question → next_question → observation → reason`，顺序即模型的输出顺序；`spoken` 属性统一取值并兼容旧字段。`normalize` 不再放行 `schema_version`，由默认值固定。
- **`SayExtractor`**（`service.py`）：增量解码流式 JSON 里 `"say"` 的字符串值，处理 `\"`、`\\`、`\uXXXX`、不完整转义与半帧；未命中键时只保留尾部 16 字符，避免缓冲膨胀。
- **拆分决策**：`_decision_context()` 在单个事务内读完所有输入（含 `decision_messages`），`_run_decision(emit=)` 承担模型调用与 `_apply`；`decide()` / `decide_stream()` 共用。规则模式一次性 `emit(spoken)`。
- **`LiveStream` + `run_decision_stream()`**：`dict[session_id:turn_id] -> LiveStream`，后台任务把增量 append 进去，`done` 在 snapshot 就绪后才置位；`call_later(120)` 回收。断开连接不取消任务。
- **`POST /interviews/{id}/answers/stream`**：先在 `database.sessions()` 里落库提交，再返回 `text/event-stream`，依次推 `ack` / `delta` / `state`（或 `error`），40ms 轮询 `LiveStream`，15 秒心跳，180 秒上限。`asyncio.create_task` 带强引用集合防 GC。保留 `POST /answers`（BackgroundTasks 非流式）作为兼容路径。
- **一致性约束**：`_apply` 改用 `decision.spoken` 作为下一问文本，`_next_turn(fallback_text=spoken)` 优先于骨架——模型已经流出去的话必须原样落库，否则页面文字会跳变。骨架因此退居兜底（`say` 为空、题库目标、模型失败）。
- **前端**：`submitAnswer` 改为 `fetch` + `ReadableStream` 手写 SSE 帧解析（`\n\n` 分帧、`event:`/`data:` 解析），`ack` 后立刻渲染并插入 `.turn.streaming` 气泡，`delta` 逐字追加 + 滚动到底，`state` 移除气泡并重建会话；首个 delta 到达即 `stopWait()`。CSS 加光标闪烁与 `…` 占位。
- **输入裁剪**：每个目标 5 条事实 × 280 字（原 6 × 400）、题库题干 5 × 160（原 8 × 200）、`observable_evidence` 2 条、最近 3 轮（`MAX_TURNS_IN_PROMPT`）、已问/历史各 4 条（原各 6）、决策 `max_tokens=500`（`DECISION_MAX_TOKENS`）。预填长度直接计入首字延迟。
- **开场提速**：`_ensure_outline(session_id, objectives=, limit=)` 改为按目标增量生成并合并写回（并发下只补缺失目标，`source` 优先 `model`）；`create()` 只 `limit=1`，`_ask_next` 在目标缺骨架时现补一次。把「开始面试」从一次批量 12 题压到 2 题。
- 提示词 `interview_prompt.v4`：明确字段输出顺序、`say` 是唯一会被念出的文本、回答过短必须 `follow_up_needed=false`。
- 文档：README 行为条目 2/3/7/8/10 改写、接口表加 `answers/stream`、已知边界重写（单进程内存通道、中间文字不重放）、交接三段重写；`docs/03` 原则段落与第 6 节实现说明同步。
- 验证：`ast.parse`、`node --check`、路由注册检查（11 条路径含 stream）；`SayExtractor` + `DecisionDraft` 离线单测（5/7/13/64 字符切片、转义、旧格式回退）全部通过。未跑迁移、pytest、静态检查、浏览器与真实模型调用。

- **根因**：`InterviewService._ask_next()` 在骨架分支里 `if not outline_text and mode == "model"` 先用后赋值，任何项目目标都会抛 `UnboundLocalError` → 接口 500 → 前端只显示「操作未完成」。场次已提交、`outline_json` 已写入，但没有首问，留下空 `active` 场次。

- **骨架必命中**：`_build_outline()` 对模型漏掉的目标调用 `_rule_outline()` 补位，避免"骨架白生成 + 即时生成"两次调用。

## 12:55 修复「没有流式输出效果」

- **现象**：页面提交回答后等 9–10 秒，文字一口气蹦出；数据库 candidate turn elapsed 5.5–10.5s、tokens 全 NULL。
- **排查**：打桩端到端（FakeStreamModel + TestClient）SSE 链路正常逐帧；直连 qwen-plus 流式正常（首帧 0.5s、say 0.8s 起逐字、真实决策输入全程 1.9s）；对运行中服务实测 9.27s 才出第一个 delta → 差异只在网络路径。
- **根因**：Windows 系统代理 127.0.0.1:65532 把 DashScope 延迟放大 5 倍（同一最小请求：直连首块 0.36s / 走代理 2.79s）。uvicorn 进程继承代理环境变量，httpx2 默认 trust_env=True。模型前 9 秒在慢速生成 schema_version/objective_status/follow_up_needed，say 第 9 秒才开始流。
- **修复**：`Settings.qwen_trust_env`（默认 false，env `INTERVIEW_QWEN_TRUST_ENV`），qwen.py 两处 AsyncClient 加 `trust_env=`；流式 payload 补 `stream_options={"include_usage": true}`，tokens 随最后一帧返回（此前流式轮次 tokens 一直 NULL）。
- **验收**（真实服务 --reload 自动生效）：新开一场（计划 70446eb0，create 4.24s 含骨架调用）→ 提交回答 → ack 0.15s / 首个 delta 0.97s / state 1.63s，tokens 1986/88 落库。
- **教训**：本地部署"没有流式效果"先查代理，再查代码。诊断方法：同一请求分别 trust_env=False / 走代理各打一次比首块时间。
- 测试场次 c33702c5 留库；上轮 3 个空场次未动。
