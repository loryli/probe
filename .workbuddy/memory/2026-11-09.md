# 2026-11-09

## Planner 收尾与面试运行时契约

接手时工作区有半成品：`planner/schemas.py`、`service.py`、`prompt.py` 已按「严格校验 + candidate_scope + interview_runtime.v1」改造，但前端、文档、测试仍停在上一轮。本轮补齐并收敛。

- 确认复核升级为内容一致性：`verify_references` 比较简历版本 `content_sha256`、项目 `revision`、事实 `content/fact_type/source_kind/evidence_quote`、题目 `content_version`；快照升到 `snapshot_version=2`，保存这些字段与题目标准答案/备注原文。旧快照（v1）在确认与 `/runtime` 返回 `plan_contract_outdated` 409，只能查看。
- `candidate_scope` 区分「可动态选用的资料池」与「目标主要依据」；覆盖率只表示目标引用比例，不再暗示未引用资料被排除。
- 题源与预算：新增 `planning_sources(snapshot, inputs)`，两种资料都有时尊重 0% / 100% 比例，只有一种时降级；来源预算先按目标数保留 30 秒下限再分配；规则模式为题库预留目标名额（`bank_groups`）并说明被省略的项目；规划漏掉某一来源时返回 `plan_source_missing`，不再悄悄改比例。
- 题目池：`ordered_questions()` 从全部启用题抽取（去掉 200 道上限），导入题按 `MarkdownImport.created_at` + `candidate_index` 还原笔记顺序，手工题按创建时间倒序；`build_snapshot` 仍按提交顺序保存。
- 模型输出：恢复 `before` 阶段格式处理（未知字段丢弃、topic/evidence/rule 截断、引用列表截到 20、`max_followups` 钳到 0–3），但 `schema_version`（默认 v2，写错即失败）、来源枚举、优先级、引用 ID 与来源范围严格校验，非法直接失败。`model_invalid_output` 文案改成通用表述（原为「未写入项目」）。
- 前端：`configDrift()` 比较当前表单/选择与 `plan.inputs`，漂移或旧契约时禁用确认并提示；`setBusy` 生成期间锁定输入（保留「读取本次结果」）；`readPending` 在任务仍 `running` 时保留 `pendingId`，`selectPlan`/`newPlan` 不再清除它；结果区新增候选范围卡片与契约版本。
- 文档同步：`docs/02` 技术栈表改为 SQLite 默认 + MySQL 保留 + 同源原生页面；`docs/03` 去掉「预算到期结束」「一次短重试」，改软预算与不自动重试；`docs/README` 同步；README 更新 Planner 章节、`/runtime` 契约、迁移头（0004/0005 的旧说法改为当前 head）与交接三段。
- 测试：`tests/test_local_database.py` 版本断言改 `0006_interview_plan`；`tests/test_question_bank.py` 表集合补到 13 张业务表 + `alembic_version`。按约定未运行。
